# 审查与修复：死亡风险模型（2026-11-18）

用户把一份Codex审查交给助手，要求“评估合理性并对合理建议进行相应调整”。本页逐项记录：审查说了什么、助手核实的结果、改了什么、对已有数字的影响、哪些要另行授权。改动都是助手的实现选择，不是用户决定；没有重新训练、没有重建真实数据表、没有读留出集。

## 1. 逐项核实

| 编号 | 审查意见 | 核实 | 结论 |
|---|---|---|---|
| P1 | “挨打前报警”名不副实：`hit_recent`＝0只表示最近3秒没挨打；100秒挨打、105秒报警、118秒死亡也算 | 读代码确认：三个脚本各自按“死前20秒内、`hit_recent`＝0、分数过线”计数，没有看更早的挨打 | **确认**。改名、改说明，加回归测试；数字不改，但不能再叫“挨打前” |
| P2 | 打在同名幻象上的伤害被算成本体挨打 | `hero_hit_seconds`只排除了攻击方是幻象，没排除目标是幻象。缓存里保留了`target_is_illusion`（抽查一场有124次） | **确认**。已修；影响见§3 |
| P2 | 表目录只要文件存在就复用，没有生成条件；读取端不检查 | 读代码确认：`build()`见到文件就返回“kept”；表里只有schema和参数；四个读取脚本直接读目录里的全部文件 | **确认**。加生成条件和读取检查 |
| P2 | 死亡代价脚本固定读`death-risk-v1` | 确认 | **确认**。改为必须指定目录并检查 |
| 结构 | B线的训练、评估集中在`scripts/`，三个脚本各写一份报警逻辑 | 确认：`train_death_risk.py`、`death_risk_by_reason.py`、`death_risk_ceiling.py`三份实现 | **合理**。按架构页原定位置（`modeling/awareness/`）做最小拆分 |
| 边界 | “加真实位置后效果提升”只说明额外信息有帮助，不能证明可知信息已被用尽，也不能直接推出要扩建地图、视野 | 助手在模型卡§1d写了“主要是因为信息不够，不是特征不够好”，说过头 | **同意**。已改写 |

审查的验证范围（43项测试、留出集按文件名检查）照它自己说的理解：文件名级检查不是完整审计。这次加的读取检查会在读每个文件时再查一次留出集。

## 2. 改了什么

**P1 报警口径**
- 统一实现：`modeling.awareness.death_risk_eval.death_alerts`和`summarize_alerts`；字段改名为`alerted_not_hit_last_3s`、`share_alerted_not_hit_last_3s`。旧报告（2026-11-17）里的`alerted_before_being_hit`不改文件，按新含义理解，契约里写明。
- 回归测试：`tests/test_death_risk_tables.py::test_alert_after_a_pause_in_the_hits_counts_as_not_hit_last_3s`（就是审查复现的100/105/118秒的例子）。
- 文字：模型卡、任务契约、当前状态、计划、复盘页说明都改成“最近3秒没挨打”。
- 事件级的“这一波第一次挨打之前报警”**没有实现**，方案写在[任务契约](b2-death-risk-contract.md)§4，等用户确认。

**P2 幻象**
- `data.death_risk.hero_hit_seconds`排除`target_is_illusion`；回归测试`test_damage_to_his_illusion_is_not_a_hit_on_him`。

**P2 表的生成条件**
- `contracts.death_risk`（只用标准库）：表的版本`death-risk-table/4`、特征名、清单格式和逐文件检查。
- `experiments.awareness.death_risk_tables`：生产端`describe_conditions`、`prepare_folder`、`reusable`；读取端`load_tables`。哈希用共享的`storage.digest`、`storage.file_hash`。
- `build_death_risk_table.py`必须给`--table`；条件不同或旧目录一律拒绝，要新目录。
- 训练、按原因报告、上限测试、死亡代价四个读取脚本都改用`load_tables`；旧目录要`--allow-legacy`，报告里写`"verified": false`。
- 测试（合成小样本）：换位置、改参数、改生产者代码、来源文件变化、目录里混了别的摘要、行属于别的比赛、留出集比赛、旧目录不加开关、旧目录里混进新文件。还在临时目录里用2场真实比赛走了一遍：写入、重跑复用、换位置被拒绝。

**P2 死亡代价**
- `death_importance.py`必须给`--table`；第一份报告的复现命令写进模型卡（`--table death-risk-v1 --allow-legacy`）。

**结构**
- `modeling/awareness/death_risk_eval.py`：交叉验证、指标、校准、按比赛重抽样、报警统计。不导入data、sources。
- `experiments/awareness/death_risk_tables.py`：表的读写检查，可以导入data（留出规则）。
- `contracts/death_risk.py`：特征名和表契约；`data.death_risk`从这里导入特征名（原名照旧可用）。
- 脚本只剩参数解析和调用。全部登记在`architecture.py`。

## 3. 对已有数字的影响

- **口径**：模型卡和状态页里的28%、30%、42%、44%、57%、72%等，都是“死前20秒内、在最近3秒没挨打的时刻报过警”的比例，**不是第一次挨打之前的召回率**。按事件级口径算，数字应该更低，但没有算，也不估。
- **幻象**：只读统计了v3表的全部112万个样本，按修复后的规则，9987个（0.89%）的`hit_recent`会从1变0，没有反方向的变化；挨过打的样本里有6.7%受影响。集中在幻影长矛手（3274）、恐怖利刃（1288）、幽鬼（1180）、露娜（1118）、主宰（741，分身斧）、敌法师（620）。会改变“最近3秒没挨打”子集的构成和平均精度等数字，方向和大小**没有重算，不知道**。
- **随机数**：按比赛重抽样改用`rng.integers`，同样的种子得到的区间会和旧报告略有不同。
- 2026-11-17的报告文件、单场复盘页第6版都没有改动，仍是修复前的结果。

## 6. 仍保留的技术债

- `gank_review.py`的`attach_risk`直接读训练报告的`out-of-fold.npz`，没有检查报告的输入是否校验过（页面只用于复盘，风险曲线按报告里的`input`字段说明来源）。
- `death_risk_ceiling.py`仍放在`scripts/`：它是一次性诊断（U165），刻意不做成可复用的模块。
- 架构测试只检查`src/`各层的导入方向；脚本只检查不跨线。评估语义靠这次加的测试，不是靠边界测试。
- 三个脚本（`build_death_risk_table.py`、`death_risk_ceiling.py`、`demo_data_card.py`）从`scripts/detect_ganks.py`导入建表输入（`match_inputs`等），运行要`PYTHONPATH=src:scripts`。这些读取函数该搬进`src/`的数据层，但`detect_ganks`的产物有冻结指纹，搬动要先登记生产者迁移，所以记为债，等路线B下一次动它时一起做（2026-11-18推送前核对架构时记录）。
