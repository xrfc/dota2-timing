# M2b 设计：赛前针对装（产品A）

状态：**评估协议于2026-10-31冻结；冻结时尚未训练、尚未看任何M2b模型结果。** 修改须新决策记录，并说明发生在看结果之前还是之后。按U12教训，本协议只允许一次正式评估；若要第二次尝试须用户另行决定，并在报告中标注。

## 1. 任务（U13、U15、U16）

在出过针对装的主宰1号位对局中（排除`collapsed_carry`，U8），根据**赛前可知的敌方5名英雄**，预测**第一件针对装**选哪件（6选1）：

| 类别 | 计入的装备键名 |
|---|---|
| 金箍棒 | `monkey_king_bar` |
| 斯嘉蒂之眼 | `skadi` |
| 碎颅锤 | `basher` |
| 散夜对剑 | `sange_and_yasha` |
| 否决坠饰 | `nullifier` |
| 净魂之刃路线 | `diffusal_blade`、`disperser` |

- “第一件”＝上述装备中首次购买时间最早者；同秒按purchase_log顺序。
- 未出任何针对装的对局（约41%）不进入本任务；页面不回答“要不要出”。
- 数据：M1快照`reports/m1-match-table-2026-10-30-v1`与其划分；训练约840、验证约240。
- 辅助针对装不建模，只显示出现率（U17）。

## 2. 输入（只用赛前字段）

对敌方5名英雄，从`knowledge/hero-capabilities/hero-registry.json`计算：

1. **定位计数**：8类`published_role_labels`（Carry、Disabler、Nuker、Escape、Initiator、Durable、Support、Pusher）各有几名敌方英雄带该标签（0–5）。
2. **机制计数**：`capability_review_signals`中每个机制维度（如healing、invisibility、dispel、summons、armor_interaction、evasion类等，按登记表实际出现的维度全集）有几名敌方英雄带该信号（0–5）。这些信号是对技能文字的自动匹配（状态`text_signal_needs_review`），未人工核对；报告须注明。
3. 特征列表由登记表决定（与训练数据无关），写入运行产物。
4. 不用：英雄逐个one-hot（样本不足）、我方阵容、任何对线或赛后字段。

## 3. 模型（实现选择，非用户决定）

- 基线B0：训练集中6个类别的比例。
- 模型M：多分类（softmax）逻辑回归，lbfgs，特征按训练集均值/标准差标准化（只用训练集拟合）。
- 正则：训练集内StratifiedGroupKFold（5折，按比赛分组，shuffle seed=0），从C∈{0.001, 0.003, 0.01, 0.03, 0.1, 0.3, 1}中选平均多分类对数损失最低者；并列取更小C。
- 不做：特征选择、其他模型族、调参搜索超出上述网格。

## 4. 评估协议（冻结）

- 数据：M1验证集中满足§1条件的对局，只用一次；不称“独立”（M1数据卡§5），独立评估在M4。
- 主指标：多分类对数损失（越低越好）。次指标：多分类Brier（各类平方误差之和）、top-1准确率（基线＝总猜最常见类）。
- 比较：M相对B0的对数损失改善，比赛级bootstrap 95%区间（1000次，seed=0）。
- **通过条件（同时满足）**：区间下限>0，且改善量≥**0.01**（最小效果量，按§8待办补上M2缺的门槛）。
- 通过→页面显示模型给出的6类概率及与基线的差，并列出影响最大的特征（系数×该局特征值）；不通过→显示基线比例并注明“敌方阵容对第一件针对装的选择无可靠影响”。
- 诊断（不改变结论）：各类别样本量、校准、系数表、混淆矩阵。

## 6. 局限（先写明）

高分段且≥30分钟比赛；每场有主宰；条件于“出了针对装”；第一件针对装也受局势与经济影响而非只受阵容；机制信号未人工核对；验证集约240，区间会较宽；“高分段常选”不等于“该选”。模型不优于基线是可能且可接受的结果。
