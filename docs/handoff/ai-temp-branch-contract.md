# AI 分支与 PR 契约（U25、U135）

2026-11-26 整理，依据已有用户决定，不新增权限。**本地从 U135 起也使用功能分支＋PR**；旧“本地只用 main”和重置/强推命令不再是本地流程。整理前原文见[历史归档](../archive/history/ai-temp-branch-contract-before-2026-11-26.md)，不能把历史命令当作当前执行授权。

## 1. 本地工作（U135，2026-11-10）

- 单仓库、单 worktree：`/home/node/.openclaw/workspace/work/dota2-timing`。共享 index、环境和文件，Git 操作串行。
- 一个主题一个功能分支，从最新 `origin/main` 开出（本会话 Codex 用 `codex/<主题>-<日期>`）。不混入其他未合并主题；必要交接通过明确版本的产物/契约。
- 开始先 `git status --short`、检查现有分支和改动，再 `git fetch origin`。保留未提交和未知文件；仅有实际冲突时暂停受影响文件。不得自动 stash、清理、reset 或覆盖。
- 新主题在确认可安全切换后执行 `git switch -c <功能分支> origin/main`。继续已有主题时复用该分支；已推送历史不改写、不强推。同步上游若产生冲突，按具体内容处理，不丢弃他人成果；无法安全取舍时请用户裁定。
- 本地提交、推送该功能分支和创建/更新到 main 的 PR 已由 U135 授权；合并 PR、直接推送 main、删除分支仍须用户同意。

## 2. 临时环境（U25，2026-10-31）

- 云端等临时容器使用自己的 `<ai名>-temp` 分支防丢失，不操作其他 AI 的 temp 分支。会话开始先拉取检查，保留远端未知提交；不得改写已推送历史。
- 可以提交、推送自己的分支并开 PR；合并、推 main、删分支仍需用户同意。旧自动重置/强推做法不应覆盖 U135 的“不改写已推送历史”。
- 云端路径、身份和数据缺失说明见计划的运行约定；没有真实数据不意味着可绕过验收或研究权限。

## 3. 提交与 PR

1. 每轮同步相关入口/API、计划 §7 或 §8、CHANGELOG、决定记录和学习笔记；开始前列出各执行者文件范围。
2. 运行专项，再由当前执行者串行运行 `scripts/check.py --scope all`；前后校验含未跟踪源码的文件指纹，漂移则重验。
3. 只暂存本主题文件。禁止提交账号、凭据、`configs/*.local.json`、`data/`、`reports/` 或未知附件。
4. 推送功能分支，PR 写清最终行为、对应决定、测试、未验证事项及前置关系。已有 PR 则更新，不重复创建。
5. 结果交用户审阅；功能完成和各分支测试通过不等于已进入 main。多个主题集成后需重新验证最终组合源码。

## 4. 冲突与权限边界

共享文件必须先重读再修改，保留他人有效改动。可以在授权范围内解决清楚的实现冲突；涉及研究语义、用户决定或无法判断的他人修改时，只暂停受影响部分并说明。

本契约不授权真实训练、联网采集、新数据用途、标签/划分变更、依赖安装、服务重启或对外发布。这些继续遵循 AGENTS 和计划 §2。协作细节见[并行开发与串行集成](parallel-development.md)。
