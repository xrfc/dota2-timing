# 长程开发提示词

将下文作为下一次开发会话的任务。开始时重新读取仓库和开放 PR，日期与上一轮的主题可以变化。

> 你是本项目的集成人。请在唯一共享工作目录完成一项当前可推进的开发，从选题、实现、验收到推送主题分支并创建面向 main 的 PR。
>
> 1. 阅读 AGENTS.md、当前状态、开发计划 §0、§2、§7、架构入口和分支交接契约。检查工作区，更新 origin/main，查阅开放 PR 的基线、实现和最新用户决定。说明主线已经包含什么，正在评审什么，哪项仍需用户提供证据。
> 2. 选择一个直接推进 §7 下一项、可独立验收的目标。写下一条用户操作、预期结果和验收方法。若下一项需要玩家试用，可交付直接支持这次试用的工具，并把实际体验留给玩家记录。涉及新的数据用途、划分、真实实验或待决研究问题时，按既有授权边界处理。
> 3. 从最新 origin/main 开主题分支。公开声明本轮涉及的具体文件。说明所需技术、选择理由及运行前提，优先复用已安装环境、现有接口和冻结证据。
> 4. 调用子 agent 分工。为每人指定互不重叠的文件、接口和专项验收。可将一人分给输入与测试，一人分给呈现，一人独立核对契约和边界情形。由你串行维护共享入口、Git index、文档和架构登记，任何人发现冲突都保留现有修改。
> 5. 在每个可验证节点运行专项检查，并从用户入口走一遍。将已完成项、证据位置、失败原因和下一项记录在计划 §7。遇到可恢复失败，诊断并复验。明确区分真实观察、合成测试和仍待人给出的反馈。
> 6. 更新状态页、相关命令和接口说明、CHANGELOG、学习笔记。用户决定记入 decisions，研究选择写清数据、标签、特征、划分与指标的依据，工程取舍署明由执行者选择。
> 7. 在同一集成窗口记录 HEAD、状态和覆盖未跟踪源码的文件指纹。复用 .venv 串行运行 scripts/check.py --scope all，比较前后指纹。若源文件变化，检查变化来源并重新验收。检查差异与暂存清单，个人配置、录像、解析产物、反馈和其他人的文件留在本机。
> 8. 提交本主题，推送功能分支，创建或更新指向 main 的 PR。列出用户可见的结果、使用步骤、验证数字、运行前提与未验证事项。检查远端提交和 PR 链接后交付。合并、删除分支和推送 main 由用户另行决定。

项目入口见[当前状态](../current-status.md)、[执行计划](../development-plan-2026-10-30.md)、[并行协作约定](parallel-development.md)和[分支契约](ai-temp-branch-contract.md)。
