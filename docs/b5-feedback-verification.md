# 从玩家反馈定位 B5 原报告

玩家从试用记录页导出 JSON 后，复盘维护者可以在本机按行找到当时那一版报告里的片段。即使两名英雄在同一秒都有决定，也能分别定位。核对只需 Python 标准库、导出文件和原始 Markdown 报告，工作台可以关闭。[试用页与导出步骤](https://github.com/xrfc/dota2-timing/blob/6ee5a538317cfd6c510d48f1e91d4abba18e932c/docs/b5-trial-notebook.md)

## 运行

在仓库根目录执行下列命令，将第一个参数换成实际下载的文件。报告根目录下应有各场的 `<比赛编号>/match-report.md`。省略 `--report-root` 时使用示例中的三场目录。

```bash
.venv/bin/python scripts/verify_b5_feedback.py ~/Downloads/b5-trial-feedback.json \
  --report-root reports/b5-three-replay-20261123
```

成功时，终端打印 `b5-verified-feedback/1` JSON。每条记录的 `report` 相对于报告根目录，`line` 从 1 起算。在编辑器打开该文件，跳到这一行即可查看原片段。记录顺序与导出一致，`feedback` 保留玩家输入的空格和换行。输出含原话和比赛标识，保存在本机。

## 核对口径

输入采用试用页的 `b5-trial-feedback/1`。命令按比赛找文件，用原始字节计算 SHA-256，核对报告标题中的比赛编号，再按游戏时刻、英雄和场景查找唯一的二级片段标题。`seconds` 必须和 `time` 表示同一时刻。仅在每条记录都能定位时输出核对结果。

| 看到的情况 | 怎么处理 |
|---|---|
| 找不到报告，或 SHA-256 与导出记录不同 | 找回生成试用页时使用的原文件。即使只改了换行，指纹也会改变。 |
| 片段定位失败、重复或时间不一致 | 核对是否拿到了原导出文件，以及对应版本的报告。错误信息在标准错误输出中，命令返回非零。 |
| 成功并返回空 `records` | 此导出内没有已保存的文字。玩家是否浏览过某场，需要其他证据。 |

工具验证的是“这段文字引用了哪一版报告的哪一行”。反馈来自谁、玩家看到时工作台实际加载了哪一版，以及动作比较是否准确，都需要各自的证据。原数据、标签、模型和评估指标沿用既有研究口径。[B5 工作台与三场试用记录](https://github.com/xrfc/dota2-timing/blob/171e42dea59254d1dd774b027962425f6d172fd7/docs/outcome-autotrain.md#三场玩家试用)
