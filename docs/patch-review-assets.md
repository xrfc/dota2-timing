## 代码接口

共享`data`模块：

- `patch_asset_evidence`：严格JSON、固定文件引用、完整捕获回执读取及发布前摘要复验。
- `patch_objectives`：`build_camp_assets`、`build_objective_observations`、`build_objective_rules`，纯计算并保留未知。
- `patch_terrain`：`StaticTerrain`的`route`、`segment`、`line_of_sight`、`render_svg`及逐秒诊断。
- `mechanics_source_equivalence`：`verify_source_equivalence`核对固定7.41f/7.42来源和完整事实行，输出逐行同一性证明、当前脚本字段证据与需要复验的文件集合。
- `mechanics_action_assets`：`build_action_assets`输出六类派生产物；可显式传入`source_equivalence_doc`，固定7.42的逐行准入政策，7.42a不能自动沿用。

B线`sources`的`map_runtime_capture.capture`和`map_visibility_capture.capture`只提取录像事实；CLI注入U133排除规则。共享层不导入B线；既有解析、地图与机制生产者不修改。

## 机制准入的证据与剩余工作

未进入补丁复核队列不等于事实失效，也不能仅凭没有差异记录就默认保留。本轮补上了两种工程核验，避免把已有证据缺少承接误写成新的用户待决。

**完整源同一性**固定旧版v26事实与7.41f/7.42来源快照。英雄逐项比较完整中英文技能对象，装备比较完整英文对象；游戏脚本按能力定义路径和英雄/物品命名空间定位，比较完整token块，保留重复键、顺序和值，仅忽略空白和注释。旧新事实整行也必须相同，包括条件、引文、备注和原审核依据。生产者输出`source_equivalent`证明；派生函数再次核对补丁、固定v26身份、候选整文和每行canonical SHA，以及两版来源摘要和语言清单。证明文件本身的字节摘要由外层CLI固定，发布前连同全部源文件复验。

源相同证明原有证据可以延续，不证明全局规则和游戏行为完全没变，也不构成本补丁用户批准。1406行具有完整源同一性，其中包含原已准入行和拒绝行，不能全部算作新增可用事实。原1165条无复核lane的行中，1134条完整同源（978条英雄、156条装备）；其余有脚本差异或缺少完整来源，需要分别处理。

**当前字段核验**仅承接已接受的事实，保留原条件和字段指针：单体指向使用`behavior & 8`且`target_team`为2或3；持续施法使用`behavior & 128`。可破坏标记要求7.42完整脚本能力块中顶层`IsBreakable`唯一出现且为`1`，重复键或多定义均不能通过。字段匹配不能覆盖待决或旧拒绝；戴泽/风行的部分破坏和六条旧U47冲突继续保留，局部作用范围随`break_conditions_en`、条件备注传递。当前注册表缺失、仅旧`extra_abilities`收录的技能，不得让特性计数获得准入；保留候选计数，供准入使用的`base`/`with_upgrades`计数字段置空。

当前同份机制输入已核验的3292行分为三个互斥组：

| 分组 | 行数 | 含义 |
|---|---:|---|
| 候选可用 | 2489 | 具备当前复核、明确裁定、完整源同一性或当前字段证据；不等于正式复盘/训练可用 |
| 明确排除 | 700 | 696条`excluded_fact`与4条已落实的用户拒绝，不属于待确认 |
| 未准入 | 103 | 69条证据不足、9条字段例外、25条待裁定既有行；三类不重叠 |

候选可用行中，1058条记为`source_equivalent`、243条记为`current_fields_verified`。原174条字段待核验中165条已承接当前证据，另有78条原未分流行通过当前可破坏字段核验。`user_approved_for_patch`仍仅8行：6条明确操作落实和2条U182保留裁定，其中4条为接受、4条为拒绝；旧`basis=user:*`和新机械证明都不会增加用户批准数量。

103条未准入的具体含义：

- **69条证据不足**：29条无lane（28条完整脚本有差异，1条德鲁伊熊缠绕缺完整双语/当前注册表证据）；39条`keep_two_ai/unclear`尚缺原审核依据；1条谜团魔晶召唤的触发条件已收窄到敌方英雄，旧事实还未落实该限制。这些不是69个用户裁定请求，脚本变化也不等于机制已证实改变。
- **9条字段例外**：7条单体指向涉及`target_team=0`或`CUSTOM=4`，通用字段规则无法证明；另外两条是米波忽悠和陨星锤持续施法，需要补固定脚本或已有例外依据。未核验不表示该能力不存在。
- **25条待裁定既有行**：8条破坏范围冲突、10条重做后的旧标签删除、3条旧用户裁定变更、2条分类分歧、1条琼英碧灵击退条件纠错、1条凯越地形。它们含15条旧接受和10条旧拒绝，不是25个独立问题，相关问题可合并评审。

**103条不是全部发布缺口。** A1全局规则、A6/A8尚未进入事实表的新技能/新机制提案（例如米波分摊伤害和投掷视野）另由`pending_topics`和[影响清单](patch-7.42-impact.md)追踪，不能写成“补完103条即可正式发布”。

已核验的机制派生结果为127个英雄档案、12项特性、164项保命手段、53个英雄与15件装备的机动清单，以及24条规则产生的3463条候选克制边。2740条边具有逐行可用证据，仍未逐对验证条件和效果（`pairs_verified=false`）；所有资产继续关闭正式复盘与训练准入。特性的未知和旧目录缺口不填成0，机动字段不冒充已验证的实际位移距离。

## 复现与完整性

`scripts/capture_map_runtime.py`接收`map-runtime-capture-spec/1`：`capture_kind`为`runtime`或`visibility`，另含`exact_patch`、原录像manifest引用、旧静态捕获及回执引用、兼容环境路径。所有引用带绝对路径与SHA-256。它验证旧回执、原demo、真实比赛/build/结束标记和完整依赖，在新进程的私有兼容副本解析，发布前再次检查资源清单和摘要。

```bash
PYTHONPATH=src .venv/bin/python scripts/capture_map_runtime.py \
  --spec reports/patch742-consumers-20261127/runtime-9103406291-spec.json \
  --output reports/patch742-consumers-20261127/runtime-new/9103406291
```

`scripts/build_patch_review_assets.py`接收`patch-review-assets-spec/1`：固定`binding`和每场`manifest`、动态捕获/回执、视野捕获/回执。完整读取state/extras至EOF，复验机制原候选全部输入、当前派生依赖闭包及捕获来源；最后原子发布独立目录。不能只改能力布尔值或状态字符串就使候选获得正式复盘或训练资格。

```bash
PYTHONPATH=src .venv/bin/python scripts/build_patch_review_assets.py \
  --spec reports/patch742-consumers-20261127/build-spec-r3.json \
  --output reports/patch742-consumers-20261127/assets-final
```

上述命令记录本轮目标目录；若输出已存在，复现时须另选尚不存在的目录。真实录像、完整捕获和报告留在忽略目录，不随Git提交。正式消费需要对应语义和游戏内验证；生成、来源完整性、机制认可、完整兼容是不同的检查。
