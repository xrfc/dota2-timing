# U26 建立最小机制知识框架（三层），替代逐条手标

- 背景：用户抽查英雄特性v1时指出朗戈的证据技能错误，并说明驱散分强驱散/弱驱散/不可驱散三类。助手核对官方`dispellable`字段，发现v1“依赖可驱散保命效果”中3条（守护天使、虚妄之诺、折光）实为不可驱散。用户问“是不是应该搭建知识框架来解决这些问题”。
- 选项：A在M2b内建最小三层框架（事实层→机制规则层→推导层），只覆盖主宰6件与辅助9件针对装（助手推荐）；B不建框架，按抽查意见手工出v2；C全英雄全装备通用知识库作为新里程碑。
- 决定：A。
- 后果：
  - 计划M2b新增T6c（事实层）、T6d（机制规则层，合并Q10）、T6e（推导层，产出hero-traits v2与触发条件）；原T7并入T6d，T8起不变。
  - 第1层草稿`knowledge/mechanics/enums-v1.json`与校验模块`dota_items.data.mechanics`；设计见`docs/knowledge-framework.md`。
  - v1标签与交叉检查报告不改；v2由规则推导，人工改动须登记理由。
- 待确认：第1层各取值含义（`confirmed`字段）。否决坠饰为弱驱散已由OpenDota物品说明给出，仍请用户确认。
- 来源：2026-10-31用户消息“我们是不是应该搭建知识框架来解决这些问题？”；助手列出A/B/C后用户回复“A”。
