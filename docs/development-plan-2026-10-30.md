## 0. 接手须知（任何模型/开发者先读本节）

1. 读本文§7。共享底座、路线A、路线B各有一个“当前任务”；**两条线没有主次（U38）**；先做完共享底座MK（U38），之后A回M2b-T6d、B进入B0，两线各自推进。只做当前任务，不做其他里程碑的任务。
2. 读该里程碑§4小节：任务、产物路径、验收标准、“不做什么”。
3. 读`AGENTS.md`（项目规则）和`docs/decisions/`（已定决策）。规则冲突以用户最新决定为准。
4. 遇到§2“待决”项或任何改变数据范围/标签/划分/采集/训练/产品目标的事，**停下来问用户**，不要自行决定；问完写决策记录（§5.3）。
5. 新想法、顺手发现的问题：写入§8待办池，不在当前里程碑内做（除非阻塞当前出口）。
6. 新增模块或脚本须在`src/dota_items/architecture.py`登记线与状态；A线与B线互不导入，共享底座不导入任一线（`tests/test_architecture.py`）。
7. 会话结束前按§6.2交接清单收尾。

运行环境：仓库根目录，复用`.venv`（Python 3.11+，已有numpy、pandas、scikit-learn、scipy；**无**pyarrow、lightgbm、torch、matplotlib，新增依赖须用户同意）。命令统一加`PYTHONPATH=src`；运行测试须去掉代理变量（shell同时设了小写`no_proxy`和`http_proxy`，只设`NO_PROXY`仍会让两条Host头测试返回502）。全库检查：

```bash
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY NO_PROXY='*' no_proxy='*' PYTHONPATH=src PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/check.py --scope all
```

## 5. 开发流程与工程约定

### 5.1 迭代
- 一周一个迭代。开始：在§7写本周目标（必须是当前里程碑任务）。结束：演示/验收收据、更新§7、本地提交。
- 在制品上限：每条线同一时间最多一个里程碑“进行中”；共享底座的进行中任务优先（U37）。

### 5.2 完成定义（DoD，每个任务）
1. 代码与单元测试；新模块按层放`src/dota_items/<层>/`，命令放`scripts/`，并在`src/dota_items/architecture.py`登记线与状态（[架构](architecture.md)）。
2. Ruff lint/format通过；全库`scripts/check.py --scope all`通过，记录前后源码指纹。
3. 有页面时：真实浏览器验收（参考`reports/decision-review-team-acceptance-2026-10-30-v3/browser.cjs`的CDP流程，Windows无头Chrome、临时配置目录，用完关闭）。
4. 产物写入新的带日期版本目录，不覆盖旧产物；`manifest.json`记录输入与源码哈希。
5. 更新§7状态；必要时决策记录。
6. 本地提交（提交信息说明里程碑任务编号）。推送/PR需用户授权。

### 5.3 变更控制与决策记录
- 须用户决定：数据范围、段位/英雄/位置范围、标签与指标、划分、联网采集、真实训练、新依赖、产品目标、删除数据。
- 决策记录：`docs/decisions/YYYY-MM-DD-主题.md`，含背景、选项、用户决定、后果、来源（哪条用户消息）。
- 常规实现（重构、测试、页面细节）无需决策记录，在提交信息中说明。

### 5.4 标注（U5）
- 客观标签由代码从比赛数据生成并有测试。
- 判断类标注：助手先标并附理由，用户抽查约1/3；报告一致率，分歧以用户为准。助手标注不作为建议质量的独立验证。
- 定义类问题由助手出方案、用户拍板并写决策记录。

### 5.5 Git
- 遵守`AGENTS.md`：本地单worktree、`main`分支，不自动切分支或重建worktree；临时环境中的AI按U25在自己的分支提交并推送。
- 小步提交；不提交`data/`、`reports/`、`configs/*.local.json`。

### 5.6 文档
- 状态只写§7。每个里程碑：设计文档（开始时）、模型卡/数据卡（结束时）。不再新建按日期的状态页。
