## 启动与使用

仓库根目录，复用已有`.venv`与本地冻结资产：

```bash
PYTHONPATH=src .venv/bin/python scripts/replay_viewer.py --port 8767
```

Windows PowerShell：

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe scripts\replay_viewer.py --port 8767
```

打开 **http://127.0.0.1:8767**。地址属于服务所在机器；其他设备需已有本地转发，本轮不创建公开入口。按Ctrl+C停止服务。默认只绑定127.0.0.1，未提供多用户认证，不应当公网服务。

1. 默认天辉可知视角；先选比赛，再选视角与关注英雄。
2. 拖动时间轴、前后逐帧或播放（1/2/4帧每秒）。时间轴按唯一采样tick排列；同一游戏秒的不同tick仍分别显示。
3. 实心点表示当前可靠位置；虚线圆表示最后可靠可见位置，旁边注明时间，**不等于当前位置**。
4. 侧栏显示存活/非存活/未知、消失/重新可见，以及当前视角能提供的质量提示。死亡坐标不当作存活位置。
5. 轨迹可关闭或选15/30/60个采样间隔；缺测、隐藏、未知、歧义不插值或跨缺口连线。跨超过45tick、1游戏秒或1200世界单位保守断线，后者只是绘图阈值，不代表确认异常位移。

播放是“每秒若干采样帧”，不是原录像实时速度。整局时间、暂停、采样不均匀时尤其不能混淆；时间轴显示tick与游戏时间，不靠插值生成新位置。

## 输入与分层

- `data/replay-quality-2026-10-26-v1/summary.json`：固定13场及每场manifest哈希。
- `aligned/<match>/{radiant,dire,omniscient}.jsonl`：对应视角数据，只加载选定文件，校验其哈希、身份与行数。
- 同包`map-calibration.json`及`data/map-reference-2026-10-26-v1/gem/assets/maps/Game_map_7.41.jpg`：底图字节哈希校验及原始图像尺寸。
- 中文英雄名来自已有`knowledge/hero-capabilities/heroes/`，未知名称回退英雄ID。

这些本地录像/模型数据不随Git克隆。未提供“没有证据时自动下载”的回退，缺少或损坏输入时明确失败。`--root`可指定同schema质量包，但地图仍对应本轮冻结来源；不支持任意补丁或任意图片。

实现：`data.replay_viewer`负责只读校验、白名单投影、tick索引、帧与轨迹；`scripts/replay_viewer.py`负责本地HTTP与严格路由；`scripts/replay_viewer_assets/`存放页面、CSS和JavaScript。不修改原始数据、既有tick对齐实现或共享数据契约。

## HTTP接口与可知信息边界

| 路径 | 内容 |
|---|---|
| `/api/catalog` | 比赛ID、公开英雄名、图像尺寸；不含轨迹 |
| `/api/timeline?match=ID&view=radiant` | 所选视角的tick/游戏时间与英雄列表；view可为dire/omniscient |
| `/api/frame?match=ID&view=radiant&tick=T&trail=15` | 该tick的状态、当前位置、最后可见位置与过去轨迹 |
| `/map.jpg` | 哈希匹配的冻结底图 |

- 阵营请求不打开或补读全知文件；隐藏/未知行若包含当前坐标或生命状态，拒绝输入，不静默信任它。
- 服务输出明确白名单，不转发原始全知字段；页面默认天辉，不预取全知视角。切换/拖动立即清空旧坐标，较晚返回的过时响应不可重绘页面。
- 全知视角也不绘制未清洗/有状态歧义的坐标；暂停和重复秒本身不视作坏坐标。同tick多条位置在显示层保留该帧但不任选位置，旧源记录不合并覆盖。
- 英雄在当前tick无采样则显示未知，不能拿上一条坐标冒充当前；最近可见历史仍可标注。视角数据只在内存短暂缓存，响应no-store；磁盘更改不会更新已加载内存快照，重启会重新核验哈希。
- 本工具是可切换全知视角的离线分析器，**不是限制观众权限的多用户系统，也不是在线无未来信息模型**。用户主动选全知后自然能看到全知信息；保证的是阵营接口和界面不暗中混用。
- 阵营实体可见性不等于地图迷雾栅格、摄像机注意力或完整游戏知识。静态底图仅12点有限视觉检查，完整地形未认证。

## 事件证据与断线含义（2026-10-26早期规划，当前实现见下节）

**已有技能和物品使用数据，第一轮回放器尚未接入事件关联。** 原始录像解析日志包含ABILITY、ITEM、MODIFIER_ADD/REMOVE、DEATH、BUYBACK。购买记录、持有装备与使用事件不同，不能互相替代；事件存在不保证完整覆盖。

原三场1,170次突跳已有逐条关联，包含跳刀、英雄技能、传送及双生门效果；扩量八场2,056次候选也已有分组证据，其中70条未命中清单、2条非存活端点待技术筛查。见[三场核对](replay-jump-events-2026-10-23.md)、[扩量记录](replay-expansion-2026-10-26.md)。不能将这些结果说成13场事件覆盖或机制归因全部完成；两个大文件恢复清洗也不自动补齐事件审计。

当前页面只接位置、可见性和状态。45 tick、1游戏秒、1200世界单位是历史实现的绘图阈值，不是用户确认的机制、速度上限或数据剔除标准。缺测／隐藏／未知／歧义属于观测不足；可靠端点间的大跨度可能来自技能、跳刀、TP、传送门或其他移动，不能统称数据异常。“断开N处”是窗口内技术计数，不是N次异常或施法；暂停、重复游戏秒本身不强制断线。

后续计划（尚未实现）：分别显示观测不足、时间间隔、大跨度跃迁；保留前后点、候选事件、时间／tick、作用角色及来源引用。例如“位置跃迁；区间内记录到跳刀使用”，不简化为唯一因果。传送或双生门效果结束可能是完成、取消或中断；同tick顺序、多候选仍保留歧义。

原始全知战斗事件不能直接注入阵营接口，实体可见也不自动证明所有事件可知。未认证事件只用于明确全知离线解释；事后上下文不能冒充当时可知信息或预测特征。具体任务与验收统一见[数据主文档](data-prep-progress.md)§18。
