# 主宰A/B阵容对比：功能与案例复盘

日期：2026-10-25。用户授权“帮我做这个吧，如果需要我判断再交给我”。
本轮是产品原型与已训练模型的探索性诊断，不重训、不读取新采集评价数据、不改变10/31前瞻采集计划。

## 1. 交付与使用

交互页：`http://127.0.0.1:8766`（服务所在机器的回环地址，其他设备需要现有端口转发）。
两套阵容分别选择双方五位英雄；可改一个或多个英雄，表格显示全部11装备的A/B概率、共同频率基线与B−A百分点。
逐装备展开可查看变化特征的精确log-odds贡献、涉及英雄的训练场数/有效标签/正例/未知数。完整阵容支持单独统计，不能用单英雄支持替代。

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python scripts/lineup_comparison.py --serve --port 8766
```

Windows在具有相同本地冻结制品的仓库中：

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe scripts\lineup_comparison.py --serve --port 8766
```

[六组案例静态报告](../reports/lineup-comparison-2026-10-25-v3/index.html)可直接阅读并展开；静态页不支持改阵容。
[全部结构化结果](../reports/lineup-comparison-2026-10-25-v3/results.json)保留所有11装备和预期，不只保留好看的结果。

## 4. 已核验与未核验分开

### 已核验的工程行为

- 11装备全部输出，不因变化方向筛掉项目。
- 全部变化贡献之和精确重建两阵容logit差；同侧调序概率不变；A/B互换后百分点差反号；频率基线不随阵容变。
- 训练支持仅来自train，加入validation行不会增加分母；未知标签不会当负例。
- 未见英雄标出unknown，不解释为学会新英雄。
- 对同一敌方英雄替换，同时改双方对照里同一友方英雄，logit差保持不变。这揭示现有模型没有显式阵容交互项；概率差仍可能因sigmoid非线性改变，二者不能混淆。

### 明确缺口，不冒称已证明错误

1. **目标覆盖缺口**：冻结11装备不含BKB，不能评估控制阵容下的BKB响应；没有自动改任务或重训。
2. **稀疏覆盖**：美杜莎组只有12场，值得优先标为支持不足；不能把一个任意场数阈值当统计可靠保证。
3. **表达能力限制**：模型仅单英雄线性相加，没有装备组合/购买顺序/显式英雄交互；不是通过本批6例得到的性能劣化结论。
4. **游戏合理性待定**：不把与直觉不同写成模型错误，也不把符合假设写成推荐已验证。
5. **机制核验未完成**：知识库未确认目标补丁机制，故不凭“幻象/闪避/法力”标签给自动解释或重新生成训练特征。
