## 营地语义

三处Dire营地可通过当前官方说明中Dark Troll名称关联，补为large候选。剩余六处是动态组成：必须核对原始单位身份、spawner handle、waiting→active、精确tick和完整观察批次，不能把只剩两只野怪或堆叠的组合解释成新营地类别。

当前直接类型、同build实测原始类型值的经验校准、历史7.38阶段规则分开记录。历史规则不是本版认证，原始枚举值也不靠旧数组顺序命名。经验映射按不同营地计证据，重复录像不冒充独立营地；冲突或未覆盖build保留未知。

## 目标复活

新提取同时保存实体生命周期、独立combat死亡事件和原始聊天事件。删除、离开网络集合、圣盾拾取不单独证明死亡；combat批量送达tick与事件原始时间分开。

同实体的死亡→再活体可直接记录观察区间；换serial关联需唯一地图刷新点、明确死亡、后续独立活体及中间的非活体观察。区间缺失、并存目标或身份歧义不补造精确计时。正样本是规则验证的证据，不代表已经确认完整基础时间、随机量或所有刷新条件。

## 视野来源和实际可见性

- 按完成网络包采样，保留当前实体、canonical英雄、原始昼夜视距、生命/等待、阵营和所有者；英雄、眼、建筑、小兵、召唤物等只先标为潜在来源。
- 两队原始可见字可导出“该身份在该采样点被记录为可见/不可见/未知”的标签。不能从没有实体记录推断隐藏，不能归因于某个眼或某个队友。
- 两队、观察者与8个自定义通道（本批共11通道）各自的树状态字、临时树生命周期、原始昼夜/FOW字段独立保留；没有树索引到世界位置的证据，不套用Workshop数组顺序。
- 基础视距不能充当修饰器作用后的当前有效视距，原始昼夜整数不猜比例解码。临时昼夜来源整数在开关关闭后仍可能残留，不单独用来判定当前状态或具体技能。目标可见性标签不等于任意坐标完整FOW地图。

世界树位数组是逐秒采样快照，相邻快照XOR只表示被观察到的位变化；同秒内切树又复原可能抵消，不能当完整砍树次数。临时树生命周期按原始entity回调记录，与世界树快照分开；临时树不套用NPC可见位语义。

紧凑捕获将实体身份、重复状态和树/可见位表去重存储，帧只保留引用；先完成整局时钟校正再归秒，赛后和被丢弃候选状态不从池中泄漏。缺秒、未知与覆盖范围在分析中显式报告。

两条肉山死亡→再次活体区间：`9103395615`为**481.4667–482.4667秒**，`9103393259`为**485.3333–486.2667秒**。唯一地图刷新点、明确实体死亡、非活体间隔和完整生命周期无并存共同支持换serial关联；删除、拾取圣盾和消息数量一致都不是单独依据。

## 模块、命令与复验

共享纯计算：`patch_camp_semantics.build_camp_semantics`、`patch_objective_cycles.analyze_objective_evidence`、`patch_vision_evidence.analyze_vision_evidence`及`iter_hero_visibility_labels`。`patch_evidence_io`负责完整补充捕获回执；B线`sources.map_objective_evidence`/`map_vision_evidence`负责原始提取。旧冻结生产者不改动。

```bash
PYTHONPATH=src .venv/bin/python scripts/capture_patch_evidence.py \
  --spec reports/patch742-evidence-20261127/vision-9103406291-spec.json \
  --output reports/patch742-evidence-20261127/vision-new/9103406291
PYTHONPATH=src .venv/bin/python scripts/build_patch_evidence.py \
  --spec reports/patch742-evidence-20261127/build-spec.json \
  --output reports/patch742-evidence-20261127/assets-new
```

捕获spec固定`kind=objectives|vision`、精确补丁及原runtime/visibility的capture+receipt摘要。新CLI复验原manifest、demo、兼容资源和依赖，使用私有Gem副本；新reader要求完整旧证据与新生产者闭包、真实结束标记和输出摘要。构建spec固定上轮资产receipt及全部新capture/receipt，严格拒绝重复比赛、通道覆盖差异和覆盖已有输出；同场两通道的manifest路径与摘要、原demo摘要、精确补丁、build、结束tick和元数据时长必须全部一致。

构建独立发布`camp-observations.json`、`camp-semantics.json`、`objective-cycles.json`和`vision-evidence.json`四份资产；营地语义的引用指向实际发布的营地观察文件，并固定其字节摘要。所有输出保留候选标记和训练/正式复盘禁用边界。

运行证据在忽略目录，验收摘要随代码分发；最终串行运行`scripts/check.py --scope all`并核验前后源码/文档指纹。具体真实统计以本轮完成后的验收记录为准。
