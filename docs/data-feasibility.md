# 主宰购买标签可行性审计

2026-10-13新增，当前审计器版本 `purchase-feasibility/3`。它审查OpenDota形状的比赛JSON，
**不生成训练集，不训练，也不签发训练准入**。复用现有购买规范化和OpenDota读取器，
不依赖Gem、pandas或GPU。

## 使用

仓库根目录运行（本轮Linux环境使用 `python3`；Windows可用 `python`）：

```bash
python3 audit_data.py path/to/match-a.json path/to/match-b.json --output reports/feasibility.json
```

本地模式不访问网络，不修改输入。也可显式请求公开比赛详情，保留原始缓存与获取清单：

```bash
python3 audit_data.py --match-id 9042638644 --match-id 9041226872 --cache data/feasibility/matches --output reports/feasibility-fetched.json
```

重复使用现有输出路径会拒绝覆盖，请选择新文件。每个请求/输入都有结果行，包括失败。
缓存存在时复用；若有同名 `.manifest.json`，审计会检查其比赛ID和原始字节哈希。
没有获取清单时仅作为本地JSON检查，不补造来源时间或真实性证明。

可通过 `--window-start`、`--window-end`（秒）和重复的 `--candidate` 指定探查窗口与候选。
默认 `[0,1800)`，候选为狂战、漩涡、幻影斧、黑皇杖、冰眼，**只是探查白名单**，
不是已验证标签词表，也不受规则推荐器暂缓装备状态控制。
此命令不把配方映射成成装；非白名单物品只统计为非候选，未实现全物品/消耗品分类。

退出码：0表示诊断完成（可以仍全部held），2表示参数/输出错误，3表示输入中存在
不可读/无效、采集失败或同场内容冲突。退出码0不能解释为训练获准。

## 报告含义

| 字段 | 解释 |
|---|---|
| `attempted_inputs` | 包括读取失败、重复与冲突的总尝试数 |
| `unique_match_ids` | 能识别出的不同比赛ID数，含冲突/失败；不是准入比赛数 |
| `inspectable_unique_matches` | 身份/结构可检查且去重后、排除冲突的目标英雄比赛数；不是语义认证 |
| `purchase_log_present_matches` | 上述分母中日志为数组的场数；空数组也算存在，不代表完整 |
| `full_window_matches` | 上述分母中时长覆盖窗口终点的场数；不证明日志连续覆盖 |
| `candidate_observed_match_counts` | 上述分母中窗口内观察到对应键的场数；零不是负标签 |
| `observation` | 只有 `observed_purchase` 或 `unknown`，不推断成装/送达/立即可用 |
| `event_refs` / `event_times` | 购买记录追踪，时间来自原始适配字段，尚未认证游戏时钟语义 |
| `scope_hints` | 比赛时间、赛事ID、rank_tier、lane_role原始整数线索；不能自动证明补丁、一号位或高分 |
| `scope` / `reasons` | 补丁、角色、高分、购买覆盖、完成语义保持未验证；短局单列截尾 |
| `training_allowed` | 固定false；现有训练门禁未改变 |

字节SHA-256用于追踪原文件；规范化JSON内容哈希用于消除空白/键顺序差异造成的重复。
同一match_id出现不同内容时，所有版本都标记冲突，不能用“后来的覆盖前面的”静默解决。
格式无效或来源清单损坏不会因另一份重复输入而被隐藏。
同秒不同装备、同键同秒重复、无效事件、配方、缺失日志和最终六格字段都单独记录。
最终六格和 `purchase_time` / `item_usage` 字段的存在不证明库存时序或合成时间。
单文件读取上限64MiB、目标购买日志上限20万行；大文件应先用专用解析管线处理。

## 真实小样本结果（2026-10-13）

读取 `/api/heroes/8/matches` 得到100条列表，**在查看详情前固定返回顺序前三场**。
没有按出装、时长或胜负挑选，不代表随机、高分、一号位或独立评估样本。
100只是发现列表长度，本次详情获取/审计分母均为3；3次全部成功。
原始JSON保留在忽略目录 `data/feasibility-2026-10-13/`，未提交玩家账号/姓名字段。
[仓库机器记录](acceptance/data-feasibility-2026-10-13.json)保留采样决定、来源、哈希及完整脱敏审计。

| 比赛 | 时长 | 主宰slot | 有效购买记录 | 默认窗口内候选记录 |
|---|---:|---:|---:|---|
| 9042638644 | 28:07 | 128 | 33 | 狂战1003秒 |
| 9041226872 | 17:59 | 128 | 21 | 狂战1003秒 |
| 9038875358 | 26:48 | 129 | 33 | 狂战797秒、幻影斧1129秒 |

3/3有购买日志，0/3时长覆盖30分钟窗口，0/3获准训练。
接口返回补丁ID60；本轮没有据此认证7.41f，也没有把lane_role=1自动当作一号位。
候选记录仅是源日志中的键和时间；即使出现成装键，也没有证明真实合成完成时间。

**结论：公开JSON值得继续审计，但这三场不能提供完整前30分钟的负标签。**
不能把“没看到黑皇杖”等当成“不需要购买”的监督，也不能缩短窗口后把探索指标说成
事先冻结的独立评估。下一步应扩展预先固定的采样清单、核对补丁/角色来源，并对成装键
和时序/覆盖做抽样对照，再决定正式标签和窗口；不开始大规模无差别采集或训练。

## 固定采样与补丁时间核验（2026-10-13 续接）

新增两个互斥入口：先冻结发现列表切片，再核对同一列表与计划后执行。冻结时不请求详情；
执行时不允许混入额外比赛或覆盖窗口/候选。计划绑定发现文件字节哈希、顺序、ID和审计配置，
**不是带第三方时间戳的预注册，也不把所有审计证据一并冻结**。

```bash
python3 audit_data.py --discovery data/feasibility-2026-10-13/discovery-response.json --freeze-plan reports/new-plan.json --skip 3 --take 10
python3 audit_data.py --plan reports/new-plan.json --discovery data/feasibility-2026-10-13/discovery-response.json --cache data/feasibility-2026-10-13/matches --patch-receipt knowledge/evidence/feasibility-2026-10-13/receipt.json --output reports/new-audit.json
```

执行加 `--offline` 只读缓存，缺文件保留为失败行；不联网也不补采其他比赛。计划、输出均拒绝覆盖。
网络失败会保留在尝试分母中，最终结果按计划顺序排列；缓存内容的比赛ID必须匹配请求ID。
发现原始列表和比赛详情保留在本地忽略目录，含玩家信息，不随本次代码交付发布。
跨机器复现必须安全提供对应原文件；不能重新请求变化后的列表来冒充原快照。

`--patch-receipt` 校验官方补丁列表、来源URL、快照哈希和带时区获取时间。
使用发布时间下界与下一补丁发布（或快照获取时间）上界；本次发布边界缓冲为1小时。
`patch_time_check` 区分 `time_consistent`、`outside_interval`、`boundary_uncertain`、
`crosses_upper_boundary`、`unknown_time`。比赛结束跨越上界也不能判为一致。
**这是时间一致性证据，不是服务器部署、客户端版本或数值patch ID的认证**；
`scope.patch` 仍为 `unverified`，`training_allowed` 仍为false。
