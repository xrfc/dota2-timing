# 7.42工程证据的候选准入与保守派生

用户继续开发后，本轮落实计划§7的“新候选生产者显式消费已补条件/目标文本”，见[授权范围](decisions/2026-11-27-mechanics-evidence-admission.md)。输入是[上一轮14条机制补证](patch742-engineering-evidence-followup.md)，没有新增采集、训练、留出使用或机制语义决定。

## 新候选与旧资产的关系

旧候选、事实、生产者和正式`current.json`保留原字节。新构建使用独立schema、策略版本和输出目录：登记基线回执→复验原输入与机制产物→重算14条补证→生成新准入→重投影依赖的候选资产→发布前复验。只有原回执SHA登记的基线可迁入，其他来源需要显式登记，不能改状态字段冒充新生产者。

准入模块保持每行原`basis`、`decision`、升级条件和用户批准；新依据放在`engineering_admission`，含结构化条件、原行状态、附件指针/摘要、未证明的能力及效果身份。谜团的“敌方英雄/每次眩晕/魔晶/不再分裂”不会被压成单独的魔晶标志。

| 本轮操作 | 行数 | 依据与边界 |
|---|---:|---|
| 提升候选资格 | 8 | 谜团1条条件收窄、7条单体指向双语文本；仍不是新用户批准 |
| 补关联条件 | 3 | 感染施加3秒撕裂伤口；治疗和吸血标签共享同一回血效果身份 |
| 降级为证据不足 | 1 | 栅栏触墙虽关联电磁排斥，但范围继承、中心/半径/受害集合未证实 |
| 继续阻断 | 2 | 米波忽悠、陨星锤仍缺引导中断行为证据 |

实际3292行：**2496候选可用、700明确排除、96尚未准入**。96包括68条原证据不足、2条引导行为、1条栅栏触发范围、25条既有待裁定。原8条7.42用户裁定保持（4接受、4拒绝），3278条非目标行逐字段不变；新候选净增7条，不能说“14条全部通过”。

## 事实资格不等于交互已证实

7条单体指向文本不能自动证明林肯格挡、莲花反弹或减益免疫交互。旧规则只按机制标签和升级条件表达关系，因此本轮采用保守投影：保留原拓扑，给受14条补证影响的节点、边和特性附完整条件，等待具体条件/交互求值；不新开可用边。

- 图中17个节点、28条边受影响，3个原候选节点及7条原候选边被收紧；新增可用边为0。不可用事实ID与“事实可用但规则条件尚未验证”分别记录。
- 特性有计数表和英雄能力明细两种视图，两处均携相同条件并执行门控。9条计数及9条能力明细受影响；受影响能力数量保持未知，旧数量另标为基线证据。
- 英雄档案每个事实恰好出现一次；英雄、技能、图节点/边及特性归属交叉核对。旧熊灵缠绕缺当前注册表归属，仅保留既有阻断节点与历史声明，不补成已验证主体。
- 新能力集合含2495个效果组，来自2496条可用事实；感染的治疗与吸血合并为同一组。这不是实际触发次数、效果量或当前可用技能数量。
- 164项保命手段和53英雄/15装备机动候选的内容保持，输出改用新schema与明确来源。它们既有局限仍在，未因本轮准入更新获得正式认证。

投影入口重新调用公开准入构建器并按严格JSON类型完整比对结果（拒绝true/1、false/0混用），不能给任意pending行伪加`engineering_admission`以绕过准入。来源层补验旧回执中的`mechanics-source-equivalence.json`输出；新派生直接指向本次新准入的最终路径和实际文件摘要，旧准入显式标为`baseline_admission`。

## 接口、运行与验收

| 层 | 新模块/入口 |
|---|---|
| 来源读取 | `data.mechanics_evidence_source.MechanicsEvidenceSource`：登记基线、公开来源读取、全依赖摘要、发布前复验 |
| 候选准入 | `data.mechanics_evidence_admission.build_evidence_admission`：重算原证据，限定登记14行变化 |
| 条件传播 | `data.mechanics_evidence_projection.project_evidence_assets`：档案、图、特性、能力分组及未变保命/机动资产 |
| 编排发布 | `scripts/build_mechanics_evidence_assets.py`：显式spec、同批输出关联、报告、原子无覆盖发布 |

纯模块只计算传入文档，不读取磁盘，不依赖workflow或模型；CLI和来源层负责验证字节。新schema拒绝被只认识旧升级条件的消费端直接当作正式知识。所有输出保持`formal_use_allowed=false`、`action_review_allowed=false`、`training_allowed=false`。

```bash
PYTHONPATH=src .venv/bin/python scripts/build_mechanics_evidence_assets.py \
  --spec reports/patch742-admission-20261127/build-spec.json \
  --output reports/patch742-admission-20261127/assets-new
```

输出新准入、五类派生、能力分组、投影摘要、HTML工程报告及回执。最终全库检查使用`scripts/check.py --scope all`，记录全部跟踪和未忽略未跟踪文件的前后指纹；运行数据不随Git分发。

## 并行核查的视野与营地缺口

这些发现用于明确后续需要什么证据，没有修改解析器或把猜测写成规则。

- 八场捕获保留的104类NPC schema均没有`m_iCurrentVisionRange`；927026个驻留状态没有当前有效视距值。基础昼夜范围不等于带修饰器后的当前范围，仅重复读取同字段无法补齐。
- 原昼夜状态包含10个临时夜样本、131个临时日样本；3404帧来源raw非零而三种临时旗标均为false。来源字段可能残留，不能据此归因。实际冻结解析器把`HeroID_t`走默认varuint32；96/270与月骑48/破晓辰星135的二倍关系只能提示编码歧义，没有引擎类型/协议证据时不自动除二或认定解析器错误。
- 7.41历史补丁文字区分T2附近淹水中营地只升级一次、赏金符附近中营地可升级两次，与部分7.42观察相容，提供待验证假设；历史说明和当前空间邻近仍不足以认证7.42的完整规则或营地身份。两个初始小营地的阶段限制仍有缺口。
- 地图2394棵树只保留坐标、没有逐树索引；世界树位图还出现8192偏移的第二组位置，不能按数组顺序直接配对。下一次补证应保留引擎树索引与坐标的明确对应，以及位图各组的语义，而不是仅增加相同格式的录像数量。

后续先补当前范围的可用来源、树索引映射及阶段规则证据；G/A/N机制与区域定义仍按[待决清单](patch742-open-decisions.md)落实。正式知识仍7.41f，7.42完整行动复盘未开放。
