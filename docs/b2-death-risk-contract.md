# 路线B任务契约草稿：预测“接下来会不会死”（U160，2026-11-17）

**状态：草稿。**方向是用户决定（U160）；下面标“助手建议”的数值和口径等用户确认后冻结。2026-11-17用户要求先做基线（U161），已按本页口径训练，结果见[模型卡](b2-death-risk-baseline.md)；口径确认前不用留出集。

## 1. 为什么改

B0想用规则判断“是不是被抓”，验收没通过（规则判“被抓”的只有约33%–73%用户认同，[B0规则](b0-gank-rules.md)§19、§21）。把它当训练目标，模型会学到规则的偏差。死亡是录像里的事实，没有标签争议，所以改成：

- **预测目标**：某一秒之后的一小段时间内，这个英雄会不会死。
- **类别只作解释**：被抓、自己深入、团战等（`data.death_tags`、`data.gank_depth`）不再是训练目标，只在复盘页上说明“这次死亡是什么情况”。类别有错不影响模型本身。

## 3. 表的生成条件和读取检查（2026-11-18，审查后补）

- 每个表目录有`manifest.json`，记录位置、参数、生产者源码哈希、知识文件哈希及其摘要；每场比赛的文件带同一个摘要和来源文件键（`contracts.death_risk`、`experiments.awareness.death_risk_tables`）。
- 条件变了（换位置、改参数、改代码、改知识文件）就要换新目录；同一目录里来源文件变了的比赛会报错，不会静默复用或覆盖。
- 读取时检查：表的版本、摘要一致、文件名和内容的比赛一致、每行都属于这场比赛、**不含留出集比赛**（在读取端再查一次，不只靠生产者）。
- 旧目录`death-risk-v1`到`v3`没有生成条件记录：不补写、不迁移，只能用`--allow-legacy`读，报告里标“未校验”。

## 4. 事件级报警：“这一波开始之前”（U171采用，2026-11-18）

现在的报警口径是“最近3秒没挨打”。真正有意义的“这一波第一次挨打之前就报警”需要先定交战边界。

**一个例子**：100秒他被敌人打了一下，跑开；105秒模型报警（这时已经4秒没挨打）；110秒、115秒又挨打；118秒死亡。

- 现在的算法：105秒那一刻“最近3秒没挨打”，所以算“提前报警成功”，提前13秒。
- 但100秒已经开打了，105秒的报警对玩家没有用。新算法把100–118秒看作同一波（两次挨打间隔不超过G秒），报警要早于100秒才算成功。
- 新算法的数字会比现在低，但更接近“能不能提前提醒”。

用户决定换成新算法（U171），并要求“一波”不能只看挨打间隔（U172）。现在的实现（`modeling.awareness.death_risk_eval`）：

- **接触的一秒**：被敌方英雄（不含塔、小兵、野怪、召唤物，U173）打的那一秒；或者他被敌方看到、并且己方看得见的敌方英雄离他不超过D的那一秒（“被看到并且自己能知道”，U172）。
- **一波**：接触的秒，间隔不超过G秒的连在一起。死亡所在那一波：结束在死亡前G秒以内的那一段；没有就从死亡那一秒算（约1%）。
- **报警成功**：死前20秒内、早于这一波开始、并且不在任何一波里的样本超过提醒线。提醒线按“不在任何一波里”的样本误报5%定。
- **一波超过20秒**的死亡没有可报警的样本，单独计数（`could_alert`），报告同时给“占全部死亡”和“占能报警的死亡”两个比例。
- **数值**：暂定D＝900、G＝5，是助手按100场试算的建议，待用户定（[重训前清单](b2-retrain-checklist.md)§2a）。表里存了每秒的挨打和接触事实（`hits`、`contact`），改数值只要重算评估，不用重建表。

## 5. 已知局限

- 正例很少（每局死几次，每次只有N秒是正例），要看平均精度而不是准确率。
- “会不会死”不等于“该不该这么做”：有的死是值得的（换掉对面核心）。模型给的是风险，不是对错。
- 死前几秒的样本很容易预测（已经在挨打），所以要把挨打中的样本分开，否则指标虚高。2026-11-17的报告只去掉了“最近3秒挨过打”的样本，停打超过3秒后又算回“没挨打”，所以那些预警数字偏高；新表改用§4的“一波”。
- 高分段数据，不代表其他分段。

## 6. 人工判断还需要多少

- 模型训练和评估不再需要用户逐个判断。
- 仍需要用户的地方：①确认本契约的N和口径（一次）；②模型出来后看少量报警例子，判断“这个提醒有没有用”（每轮约20个，不是逐个定类别）；③复盘页上的类别说明如果要改进，仍要用户意见，但不阻塞模型。

覆盖率以目标位置英雄的去重死亡总数为分母，包含首次采样前、缺采样窗口及整场没有预测样本的目标英雄。报告同时列出 deaths、deaths_with_samples、could_alert 和 alerted_before_fight；无样本死亡的峰值为空。
