# 7.42决策时可知证据：读取、验证与工程报告

本轮按用户“按照你的建议，沿我们的开发路线进行长程开发，自己检验自己验证”推进，见[决定记录](decisions/2026-11-27-decision-evidence.md)。复用已有八场7.42工程录像，将[补证资产](patch-evidence-followup.md)接到统一的时点读取接口；这一步验证证据能否安全进入后续复盘，不训练、不打行动分，也不开放正式7.42复盘。

## 当时观察与事后核对

`known_view`只保留截至显式游戏时间和录像tick的观察。完整来源摘要在`provenance`中；营地演变、目标死亡/复活和其他整局诊断放在独立资产及报告的“事后工程核对”部分。报告不是盲评页，看到事后内容后的意见不能当独立评价。

- 使用实际`frame.game_time`和`frame.tick`双重上界，不把整数秒标签当作包发生时刻。同一秒内较晚的包不能提前进入查询。
- 查询必须显式给出`max_age_seconds`。过期、超出录像结束范围或无法证明时间范围时返回未知；游戏时钟年龄和tick年龄分别报告，暂停期间不换算固定tick率。
- 捕获边界为completed packet，但没有tick内packet序号；`exact_tick_match`只证明tick相等，不声称恢复了同tick内的每一次输入时刻。
- 可见位先于阵营分支：隐藏实体的team、血量、位置、类别或canonical归属不能改变己方输出。没有可信事前完整名单，因此`friendly_roster_complete=False`是“未认证完整”，不是“已发现少人”；不能用全知状态填未知队友槽。
- 己方canonical本体在可见位、身份和出生条件满足时提供原始生命/生命状态；非存活本体位置不提供。其他可见活体只提供身份、类别/首次登记名称、阵营和位置，不提供敌方血量、真实本体归属、所有者、装备、当前视距或单位状态位。
- 暂时未观察到目标不等于目标已死；未观察到营地单位不等于空营地或封野。可见中立单位位于某触发区域，只证明该采样点的位置，不证明出生营地或完整存量。
- 原始营地类型变化、整局组成推断和目标复活区间没有进入事前输出；当前阶段、存量、封野、战术区域、目标刷新倒计时继续未知。

## 接口与低耦合边界

| 模块 | 职责 |
|---|---|
| `data.patch_decision_source` | 校验固定产物、原始比赛身份、许可范围和完整来源；逐场读取，发布前复验 |
| `data.patch_decision_view.VisionDecisionIndex` | 纯计算：双时钟查询、可见门、白名单投影；不访问文件，不读事后目标/营地资产 |
| `data.patch_decision_context.DecisionContextIndex` | 只组合已过滤视图与静态候选触发区域；不接受动态阶段或cycle作为输入 |
| `data.patch_decision_validation` | 独立原字算术与身份核对、严格截断查询、未来/隐藏内容扰动验证 |
| `data.patch_camp_diagnostics` | 共享纯计算：未关联句柄与阶段边界的事后诊断 |
| `data.mechanics_engineering_evidence` | 共享纯计算：固定双语来源与结构化条件证明，保持旧准入和用户裁定 |
| `scripts/build_patch_decision_audit.py` | 显式spec编排、静态HTML报告、原子无覆盖发布 |

`VisionDecisionIndex(capture, exact_patch=..., source_ref=...)`构造时验证完整捕获；`at(game_time=..., replay_tick=..., observer_team=2|3, max_age_seconds=...)`返回独立对象。调用方必须先验证字节来源。Context调用同样四项查询参数，输出来源不与内部对象共享可变引用。

读取层先核capture receipt声明及其manifest里的真实比赛身份，再检查允许范围；随后复验来源文件。顶层输入清单必须恰好等于基线、捕获、登记生产者及固定文本的并集，拒绝无引用的额外文件；同场两通道必须来自相同原录像/manifest/build/结束tick。仍继承已登记旧回执的可信来源边界，哈希不是对任意来源的权限签名。

## 验证与工程探针

复用原五场及上一轮补采三场，没有新增联网请求或训练用途。上一轮是约定最多3场已完成，并非平台/API或流量配额耗尽。

本轮实现选择：固定探针秒为0、60、600、899、900、901、1799、1800、1801、2400，取目标秒之后该秒内首个实际采样点并同时记录真实time/tick；两队均生成卡片。未覆盖的时刻跳过并记录覆盖。这是工程取样，不是用户确认的训练标签、评价抽样或决策触发规则。最大游戏时钟年龄显式设1秒，仅作接口验证；发布的卡片使用精确采样点。

所有游戏秒均检查双队精确查询，以及更早1微秒/更早1tick查询；逐项重算原可见字、身份、位置和己方HP。另在每场约900秒处，修改未来未引用状态，以及当前隐藏实体的位置、HP和阵营，比较较早的`known_view`是否不变。完整捕获内容摘要预期会随扰动改变，不把摘要本身当特征；扰动验证不等于另一套解析库或游戏内可见性认证。

```bash
PYTHONPATH=src .venv/bin/python scripts/build_patch_decision_audit.py \
  --spec reports/patch742-decision-20261127/build-spec.json \
  --output reports/patch742-decision-20261127/audit-new
```

输出`decision-contexts.json`、`decision-validation.json`、`camp-diagnostics.json`、`mechanics-engineering.json`、`report.html`及回执。旧捕获生产者、旧报告和正式知识入口保持原字节。最终全库验收使用`scripts/check.py --scope all`，记录包括未跟踪源码在内的前后文件指纹。

## 八场实测结果

本轮最终回执固定1254个输入文件，输出5份数据/页面及1份回执。8场精确7.42/build6993覆盖15445个游戏秒，完成30890次双队精确采样查询、61780次更早时间/tick边界检查、154450次己方原始状态和3268761次可见活体字段核对。八场各做一次未来状态扰动及两队隐藏状态扰动，修改行数均非零，较早已知视图保持不变。

固定探针生成120张卡片；20个比赛/目标秒超出捕获时间范围，按原因记录（对应5场短局各4个晚期目标秒），不是观察到负结果。三场长局各20张，五场短局各12张。

固定卡片未命中目标活体可见时刻，因此另对已有八场中的429个肉山、37个痛苦魔方可见样本运行真实Context接口，覆盖458个唯一正例查询（8次同时可见两个目标）；另做225次肉山旗帜负控，共683次查询全部通过。未见的另一目标仍保持未知，旗帜不会被当作肉山。本项事后选择正例，只验证工程分支，不作为效果评价，也没有改动固定探针spec。
