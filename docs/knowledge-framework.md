# 机制知识框架（U26，2026-10-31；U27扩为完整版）

> **U27（2026-10-31）**：范围由“M2b的15件针对装”扩为**全英雄（含A杖/魔晶）＋全部可购买装备**，作为新里程碑MK（计划§4），中立物品与天赋以后再加。下文§4“只覆盖15件”已被替代；三层设计不变。当前任务MK-T1：机制词表（§5）。

## 1. 为什么要建

英雄特性v1（U23）从技能描述文字直接跳到“某英雄有某特性”的人工判断，中间没有结构化的机制事实。用户抽查发现两类错误：

- 证据技能写错：朗戈“高机动”引用了灵呱一闪（给队友降蓝耗），实际相关的是动人之舐（把目标拉回一小段距离＋弱驱散）。
- 机制判断错：官方数据自带`dispellable`字段，v1未使用；按该字段，守护天使、虚妄之诺、折光均为**不可驱散**，却被标为“依赖可驱散保命效果”。

框架把“依据”显式写出来：用户审规则而非逐条审标注，规则对了，127位英雄的结论随之正确；补丁更新时重算即可。

## 2. 三层结构

| 层 | 内容 | 谁定 | 位置 | 状态 |
|---|---|---|---|---|
| 1 事实层 | 官方原始枚举的含义，每个取值附已知技能作核对例子 | 数据自带；含义由用户确认 | `knowledge/mechanics/enums-v1.json`，`dota_items.data.mechanics` | 草稿，待确认 |
| 2 机制规则层 | 每件针对装克制什么机制，写成可执行规则；引用第1层字段与装备官方说明 | 用户定，助手起草（即Q10） | 待建（M2b-T6d） | — |
| 3 推导层 | 英雄特性、触发条件，由规则自动算出，每条附证据链；人工改动须写理由 | 自动；用户抽查 | 待建（M2b-T6e，hero-traits v2） | — |

依赖方向：3→2→1→官方快照。第1层不含判断；第2层不直接读文字描述做判断（可引用作证据）；第3层不手填结论（例外须登记理由）。

## 3. 第1层当前内容（v1草稿）

解码字段：`dispellable`（0无可驱散效果/1仅强驱散/2弱驱散可驱散/3不可驱散）、`target_team`（无/友/敌/双方/自定义）、`damage`（无/物理/魔法/纯粹）、`type`（普通/大招）。

- 依据：Valve引擎枚举定义顺序推断，并用已知技能逐值核对（例：薄葬、回光返照、决斗→3；妖术、沟壑→1；风行、无光之盾→2）。
- 校验：`load_enums`要求每个例子技能存在且取值一致，且登记表中出现的每个取值都有解释；补丁带来新取值会直接报错，不会被默默猜测。
- 暂不解码：`immunity`（0–5的含义未能稳定核对）、`behavior`其余位、`target_type`。
- 局限：快照未核对补丁（`patch_verified=false`）；`confirmed`全部为false，等用户确认。

装备侧已知事实（第2层将引用）：否决坠饰主动“Nullify”为**弱驱散**（OpenDota dotaconstants物品说明`Dispel Type: Basic Dispel`，`knowledge/items/sources/dotaconstants-items.json`）。

## 4. 复用与不做

- 复用`knowledge/recommendation/7.41f-v1/knowledge.json`的事实格式（来源指针＋原文引用＋中文摘要＋条件），第2层沿用。
- 范围只覆盖主宰6件针对装与辅助9件（U15、U21）；不做全英雄全装备通用知识库（用户未选C）。
- 不改冻结产物：hero-traits v1、交叉检查报告v1保持原样；v2另建。

## 5. 机制词表（MK-T1，草稿待用户拍板）

`knowledge/mechanics/vocabulary-v1.json`：42项机制、9类（控制、防御/保命、状态与驱散、生命/法力、单位、位移、伤害、攻击修正、施法方式）。每项有定义与判定依据：

- `enum:X`：已解码的官方枚举（如`effect_dispellability`用`dispellable`，伤害类型用`damage`）；
- `field:X`：技能原始字段（如法力消耗数值、`behavior`位掩码）；
- `official_text`：官方说明中的明确表述（如“施加破坏效果”“破坏会使……失效”）；
- `manual`：人工判断（目前没有项只靠人工）。

`load_vocabulary`校验编号唯一、类别存在、依据类型合法（`enum`必须是已解码字段）。

与v1的关系：v1的9个特性拆成更细、更客观的机制，例如“依赖可驱散保命效果”＝防御类机制（免死、护盾等）×`effect_dispellability`；“高机动”拆为`self_mobility`与`displace_other`（朗戈动人之舐属于后者）；新增破坏、隐身/真视、沉默、减益免疫/穿透、持续施法等。

待用户回答（词表中`open`字段）：

1. 闪避与致盲分开还是合并？（v1交叉检查两者效果方向相反，助手倾向分开）
2. “受破坏影响”是否只算整体失效？（剑心犹在等仅不能获得新叠加，助手倾向不算）
3. “法力依赖”的门槛：蓝耗合计无法单独区分，是否改为人工判断或用别的指标？
4. 减益免疫：`immunity`枚举未能核对，暂只用说明原文——是否接受？
