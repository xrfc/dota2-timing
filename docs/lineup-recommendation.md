## 运行

从仓库根目录执行；`recommend.py` 自动使用项目 `.venv`。只需基础依赖，无需 Gem、
pandas、训练框架、API key、网络或游戏客户端。

```bash
python recommend.py examples/recommendation/baseline.json --format text
python recommend.py examples/recommendation/illusions.json --format json
python recommend.py examples/recommendation/baseline.json --format html --output reports/lineup.html
```

输出文件必须不存在，避免覆盖输入或旧结果；再次运行时使用不同文件名或省略 `--output`。
可直接用浏览器打开生成的 HTML，不需要启动服务器。HTML 无外部脚本或网络请求。

安装包提供 `dota-recommend`（更新安装后可用）；该入口必须显式传入知识包，避免在任意
工作目录下误用另一份知识。源码模块入口等价：

```bash
python -m dota_items.recommendation.cli examples/recommendation/baseline.json --knowledge knowledge/recommendation/7.41f-v1
```

退出码：`0` 为成功产生完整或部分分析（不等于质量验收）；`3` 为输入合法但组合/目标知识
不支持，并正常输出原因；`2` 为非法输入、知识损坏或输出失败，错误 JSON 写到 stderr。
未知英雄 ID 与目录内英雄缺少机制知识分开处理。

## 输入与结果

输入仍使用[阵容契约 /1](recommendation-contracts.md)，不接收命石、当前库存或经济。
位置由调用者明确指定。首版英雄目录包含127个身份；它们都可以出现在双方阵容中，
但只有 `(hero_id=8, role=1)` 已启用推荐策略。其他目标组合不自动回退。

CLI 输出 `coach-lineup-analysis/1`：

- `recommendation`：原 `coach-lineup-recommendation/1`，保留完整输入、指纹、版本与事实引用。
- `needs`：触发需求/风险的阵营、事实、规则与条件。队友控制只表示潜力，不扣除自身生存需求。
- `exclusions`：范围内候选未输出的原因，包括暂缓事实/交互、不适配及无触发需求。

报告分早/中/后期显示核心方向、针对方向和备选，而不是按总分给一条购买顺序。
分数为未校准规则权重。同一事实需求命中多个英雄时保留所有引用，但不按人数重复加分。
同分以装备 key 稳定排序。狂战/漩涡处于“首件发育大件”选择组，次选明确为备选，
不是要求连续购买两件。

`supported` 仅表示十英雄均有首批规则可用摘录且目标策略可用，**不是所有技能、交互或
推荐质量均已验证**。`partial` 保留阵容内未覆盖英雄；缺失不能当作无威胁。
若目标必需事实缺失/冲突则 `unsupported`，不生成建议。已知英雄的冲突事实会阻止使用
该英雄的全部事实，待协调后再恢复；装备事实冲突则过滤对应装备。

## 首批知识和候选

[知识包](../knowledge/recommendation/7.41f-v1/knowledge.json)保存27份来源的哈希与 URL、
26条逐条摘录和条件：12位英雄的14条机制摘录，以及12件装备的文字效果。
全英雄历史档案不因此整体变成7.41f已核验知识。

启用候选：动力鞋、狂战斧、漩涡、幻影斧、金箍棒、碎颅锤、斯嘉蒂之眼、撒旦之邪力、
闪烁匕首、魔杖。候选需命中需求才输出，并非每场全部出现。
黑皇杖与蝴蝶保留在范围清单但暂缓启用，原因随结果展示；不等于认为它们不值得购买。
未纳入的装备暂不评估；树枝、卷轴和消耗品不作为目标。没有价格/合成的完整审计，
本版不生成购买预算、配方步骤或精确完成时机。

来源详情接口没有 patch 字段。本包采用 `official_current_crosscheck`：
官方补丁表当前末版与官方7.41f明细一致；狂战主动冷却、幻影斧远程幻象伤害、撒旦基础
吸血三个值与7.41f改动锚点匹配。核验发生于2026-10-11，保存的表及快照不会运行时刷新。
此关联**不是游戏 build 证明或客户端逐机制验证**，无法排除官网遗漏或静默变化。

`verified` 表示本轮开发者（AI）逐条核对了引用文字、归属及上述版本关联，不表示用户
逐条审核或实战认可。事实只采用文字支持的窄结论，不解释未确认的枚举或占位数值。
例如只把沉默与基本驱散建立为有条件的候选关系，不声称所有沉默都能驱散；敌方控制
只保留风险，不机械导出黑皇杖必出。策略权重与“发育价值”等战术判断独立保存在规则包，
不是伪装成官方事实。知识核验不解除旧真实训练 held。

## 全英雄、全位置如何扩展

依赖方向：`CLI → 文件适配器/纯推荐核心/报告`。核心只接收不可变值对象；不导入回放、
工作流或训练模块。I/O边界目前足够小，不增加通用规则平台或空接口层。

1. 为新英雄补充带来源、条件、冲突状态的事实；已有目录外的新英雄还需更新冻结身份目录。
2. 在新版本规则包 `profiles` 中增加对应 `hero_id + role`、必需事实、候选白名单、
   `item_rule_ids` 与策略依据；每个组合可选择独立权重规则，不污染其他组合。
   `role` 支持1–5，不把英雄名字自动解释为位置。
3. 在已有机制标签上配置需求规则、装备规则、条件和启发式权重；必要时增加新的机制逻辑。
4. 用新组合案例验证效果与边界后再声明支持。不能仅复制主宰权重给其他英雄。
5. 用新版本目录保存来源/规则并指定 `--knowledge`，不覆盖旧包；旧推荐仍可由原哈希追溯。

核心代码没有 `hero_id == 8` 或 `role == 1` 的业务分支。回归测试通过仅修改测试内的策略，
验证另一英雄/位置可运行并仍受近战装备限制；**这不启用正式范围之外的推荐**。

当前 schema 固定7.41f；扩展英雄/位置不需要改该 schema，跨补丁支持则须单独版本化和验证。
新增复杂交互或团队联合分工不是简单加一条配置，需独立机制建模与验收。

## 案例与验收边界

[案例清单](../examples/recommendation/cases.json)记录6个开发者构造的输入，均为合成案例，
不是搜索到的职业比赛，不包含真实玩家数据。对其余九人的位置不作隐式分配。

| 案例 | 预期行为 |
|---|---|
| baseline | 检出沉默、闪避、治疗及控制风险；保留有条件的装备方向 |
| no-evasion | 幻刺换暗影萨满，命中需求消失；不再因本包闪避事实推荐金箍棒 |
| illusions | 小黑换幻影长矛手，多目标需求出现；发育路线备选优先级改变 |
| unknown-hero-knowledge | 幻刺换祈求者，身份合法但机制缺失，输出部分分析 |
| unsupported-role | 二号位主宰不自动套用一号位规则 |
| unsupported-target | 三号位昆卡不自动替换为主宰 |

工程回归另覆盖队友替换、来源损坏、错误版本、引用归属、冲突、全候选被过滤、队内
换序不变、禁用回放/网络后的端到端运行、HTML转义与输出防覆盖。
这些案例和规则共同开发，**不是独立盲评集**。M06仍待：使用未参与调参的案例，
预先冻结评审问题与门槛，比较简单固定路线基线，逐条复核不合理建议及未覆盖交互。
当前不报告推荐准确率、提高胜率或概率置信度。

下一轮按[质量评审流程](recommendation-quality-review.md)执行：先评现有报告，补齐控制/
驱散/免疫交互，再冻结策略与未参与调参的最终集。2026-10-11文档更新当时只确认执行计划，
不调整候选或权重、不将开发案例转为盲评案例。

源码：`recommendation/knowledge.py`（数据契约）、`files.py`（来源验证）、`engine.py`
（需求/硬约束/排序）、`report.py`（纯渲染）、`cli.py`（入口编排）。
