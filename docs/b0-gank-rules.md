# B0：“被抓”可执行规则（2026-11-09）

状态：**第一版已实现（U131，2026-11-09）；U132（2026-11-10）改为只评1号位、被抓死为主要结果；U133留出20%比赛、U134分层抽查，第二轮结果见§8。§7是1、5号位一起、未留出的第一轮，仅作历史。**，等用户抽查实例后冻结为B0任务契约。定义来自U115、U116（`docs/decisions/2026-11-07-b0-gank-definition.md`）；§5的问题用户已答（U131，`docs/decisions/2026-11-09-b0-gank-rules.md`）。阈值是助手建议、用户同意先这样跑，筛出实例后再调。

## 1. 一次“被抓”怎么认（流程）

对每个被评价的玩家（当前`positions=(1,)`，U132；作为参数传入，U116）：

1. **起点**：敌方英雄对他造成第一次伤害或控制的时刻（战斗日志）。前面10秒内他没被敌方英雄打过，否则算同一次。
2. **窗口**：从起点往后20秒（U115暂定）。
3. **参与的敌人**：窗口内对他造成伤害或控制的敌方英雄；要求**≥2个**。
4. **结果**（U115选b）：
   - 窗口内死亡 → **被抓·死亡**；
   - 没死，但窗口内用了“保命手段”（§2） → **被抓·交出保命手段逃掉**；
   - 没死也没用 → 不算被抓（只是被打）。
5. **排除大团战**（§3.1）。
6. 另外两个条件**“从视野外出现”“离队友远”**（§3.2、§3.3）：U115说先四条一起筛。

## 2. 保命手段清单（从机制知识库推出）

一个技能或装备算保命手段，需要同时满足：**主动使用**（被动不算，有冷却或充能）、**作用在自己身上**（或队友对他用，见问题2）、机制属于下面A组（或用户勾选的B组）。施放时刻从战斗日志读，解析器v3的冷却可以核对“确实用掉了”。

| 组 | 机制（词表v15） | 知识库里的数量（接受的事实） | 例子 |
|---|---|---|---|
| A 核心 | 自身位移 | 技能71、装备15 | 闪烁匕首、原力法杖、回城卷轴、敌法师·闪烁 |
| A | 隐身 | 技能21、装备6 | 微光披风、影刃、暗影护符、诡计之雾 |
| A | 无敌/不可选取、吹风/放逐（对己） | 技能34＋3、装备3＋4 | Eul的神圣法杖、风之杖、幻影斧（分身瞬间） |
| A | 减益免疫 | 技能15、装备1 | 黑皇杖 |
| A | 免死 | 技能7 | 薄葬、回光返照、虚妄之诺（U117） |
| A | 虚无（对己） | 技能5、装备3 | 幽魂权杖、虚灵之刃 |
| A | 施加强驱散（对己） | 技能13、装备1 | 永恒之盘 |
| B 待定 | 加速：只算U121确认的16个逃跑加速技能＋加速装备 | 技能16（另75个不算）、装备25 | 风行·风行、白虎·跳跃；相位鞋、疯狂面具 |
| B | 施加弱驱散（对己） | 技能30、装备9 | 散魂剑、清莲宝珠 |
| B | 幻象 | 技能22、装备1 | 幻影斧、娜迦·镜像 |
| B | 护盾/减伤 | 技能38、装备9 | 赤红甲、洞察烟斗、先锋盾 |
| B | 格挡指向技能 | 技能1、装备1 | 林肯法球（被动也会触发） |

说明：

- 数量来自事实v26的接受行，同一技能多个机制会重复计数；“作用在自己身上”还要逐个技能按`target_team`或说明核对，确认后才生成最终清单。
- 回城卷轴单独处理：被抓时TP走需要读条，读条被打断不算用掉。建议按“传送完成”算保命。

## 3. 三个阈值

距离单位是游戏坐标（地图约16000×16000，一个塔的攻击距离约700）。

### 3.1 不在大团战（建议）

窗口内，以被抓者为中心1600范围内，**双方英雄合计≤6个**，且**我方（含被抓者）≤2个**。超过就记为团战，不算被抓。

### 3.2 从视野外出现（建议）

参与的敌方英雄里，**至少1个在起点前5秒内对我方完全不可见**（现有解析每秒有阵营可见性）。

### 3.3 离队友远（建议，按位置分别记）

起点时，离被抓者最近的我方英雄距离**≥1500**（1、5号位先用同一个值，按U116分位置记录，以后可分开调）。

## 4. 怎么校准

U115定的是先筛后查偏差。解析器v3跑完已采demo后：

1. 按上面规则跑一遍，统计每场被抓次数，以及每个条件各筛掉多少；
2. 随机抽20个“算被抓”、20个“差一点不算”的实例，给用户在录像里看是否符合直觉；
3. 有偏差再改阈值，改动和理由记决策。

## 5. 当时要用户确认的问题（已由U131回答）

1. 保命手段先用A组，B组哪些也算？（加速只算16个逃跑技能＋加速装备？弱驱散、幻象、护盾、林肯？）
2. 队友对他用的保命（如队友的原力法杖、微光披风、薄葬）算不算“他交出保命手段”？还是另记“队友救下”？
3. 三个阈值先按§3的建议跑，筛出实例后再调，可以吗？
4. 起点前10秒没被打过才算新的一次——可以吗？

## 6. 用户回答（U131）与实现

| 问题 | 用户回答 | 实现 |
|---|---|---|
| 1 保命手段 | A组都算；B组加速、弱驱散、幻象、林肯算，护盾/减伤不算 | `knowledge/awareness/save-means-v1.json`：166项（技能133、装备33） |
| 2 队友对他用的保命 | 算被抓，同时记“队友救下” | 结果分`self_save`、`ally_save`、`self_and_ally_save` |
| 3 阈值 | 先按§3建议 | `data.gank_events.PARAMS`，位置作为参数 |
| 4 新的一次 | 先按建议：前10秒没被打过 | `quiet_gap = 10` |

实现细节（助手选择，抽查时一起看）：

- **保命手段清单怎么生成**（`scripts/detect_ganks.py save-means`，从知识读取接口读事实v26）：技能排除被动和只能指向敌人的（游戏文件`behavior`、`target_team`）；加速技能只算U121的16个；装备的加速只算**主动效果**带加速的12件（相位鞋、疯狂面具、韧鼓、宽容之靴、微光、影刃、白银之锋、诡计之雾、炎阳纹章、散魂剑、克莱拉牧杖、迅疾闪光），只有被动移速的鞋子、动力鞋切换、散夜对剑等不算。
- **怎么认用了**：战斗日志里有施放记录；自己对自己、对队友或不选目标的施放才算，对敌人用的不算（如推推推敌人）；回城要在8秒内真的移动2000以上才算。
- **“被打”只看伤害**：起点和参与的敌人都按敌方英雄本体造成的伤害算；只有控制没有伤害的、召唤物和幻象造成的不算。
- **“从视野外出现”**：起点前5秒内，某个参与的敌人**有任意一秒**对我方不可见。
- **位置**：采集的OpenDota信息没有分路数据，按U8的规则在录像上推：1–10分钟大部分时间在本方优势路的两个英雄里，15分钟正补多的是1号位、少的是5号位，差不到25则不定。

## 7. 第一轮结果（162场，`reports/gank-episodes-2026-11-09/`）

- 候选（1、5号位被敌方英雄打到的每一段）18700段，算被抓1294次，平均每场每个1、5号位约2次；1号位757、5号位537。
- 结果：死亡953（74%）、自己保命逃掉324、队友救下6、自己加队友11。
- 只差一个条件就算的：离队友近1356、敌方只有1人790、属于大团战486、没死也没交保命304、敌人一直在视野里138。
- 自己保命里最常见的是相位鞋（166次）、敌法师闪烁、敌法师法术反制、幻影斧、主宰剑刃风暴。相位鞋很常在追人或打架时开，不一定是逃跑，需要抽查决定是否保留。
- 抽查清单：`reports/gank-episodes-2026-11-09/sample.json`（固定随机种子，20个算被抓、20个差一个条件）。

## 8. 第二轮（2026-11-10，U132–U134，`reports/gank-episodes-2026-11-10/`）

- **留出集（U133）**：`data.awareness_split.is_holdout`，按比赛ID加盐哈希取20%；`detect_ganks.py run`跳过它们（本轮跳过55场，用238场）。冻结前的第一轮在161场上跑过，其中34场落在留出集；展示过例子的34场比赛中有9场落在留出集。这些比赛被看过的只有汇总数字和那几个例子，阈值还没按它们调过；如实记录，不移出留出集（规则只看比赛ID）。
- **结果（只评1号位）**：238场、1030次被抓，平均每场每个1号位2.16次；被抓死654（63%）、交出保命逃掉376。
- “交出保命逃掉”里最常用的：相位鞋84、敌法师闪烁59、幻影斧51、回城40、主宰剑刃风暴38；只靠相位鞋算逃掉的23次。

- **分层抽查（U134）**：`sample.json`三层各20个，表格`review.md`（给用户填）。按层报准确率；一层20个的准确率误差约±20%，需要时再扩到每层40个。
- 待查：只控制不造成伤害的先手（起点按第一次伤害算，会晚一点；控制没伤害的整段会漏）。

- **判断**（2026-11-11改，U139）：不再选对／错（分不清是在判“是不是被抓”还是“规则对不对”），改为直接选这次属于哪一类——被抓、自己深入、高地上、其他、不确定，加一句原因；页面顶部写明规则的判定，左侧清单标出你选的和规则是否一致（＝／≠）。存到同目录`judgments.json`（本地，未跟踪）。此前14个对／错判断里，含义明确的10个已换成类别，D7、D12、D13、D14留空待用户重选（批注保留，原文件备份为`judgments-right-wrong-backup.json`）。
- **这是全知视角**：回放含双方全部位置和之后发生的事，只用于抽查和作标签，产物里写了`use: review_and_label_only`，不能作模型输入。
- **开雾（用户：开雾不是保命装备，是抓人常用）**：
  - 诡计之雾从保命手段里去掉。现有结果里它只被算过1次、没有只靠它逃掉的，本轮60个抽查实例不受影响；清单v2在下一轮重跑时生成。
  - 新增“开雾而来的敌人”：战斗日志里`modifier_smoke_of_deceit`的添加和移除配成区间，参与的敌人在起点前30秒内处于开雾状态就算（30秒是助手选的，开雾靠近敌方英雄会自动破掉，所以往前看一段）。60个抽查实例里：被抓死3/20、交出保命逃掉2/20、差一个条件0/20有开雾而来的敌人。样本小，只能说明字段能取到，不能下结论。
  - 目前只是记录字段，不是“算不算被抓”的条件。待用户抽查后定：是否作条件、或单独作为一类“开雾抓人”。全部实例上的统计在下一轮重跑时给出。

## 10. 第三轮：自己深入、高地、开雾（U136–U138，2026-11-10，`reports/gank-episodes-2026-11-10-r3/`）

用户判了10个“被抓死”后指出两类不该算被抓（决策记录U137、U138）。四个条件（§1）不变，在它们之上再分类：

| 最终归类 | 含义 | 认定 |
|---|---|---|
| 被抓死、交出保命逃掉 | 被抓 | 四个条件都满足，且不属于下面两类 |
| 自己深入 | 1号位主动进了敌方控制区被打，不算被抓，单独保留（U137） | 在敌方控制区，且四条主动迹象至少一条 |
| 高地上 | 起点在任一方高地，不考虑（U138） | 沿两泉水连线越过中线6000以上 |

每段记录`rule_label`（四个条件的结果）和`label`（最终归类），以及`depth`里的六个信号和数值（`data.gank_depth`）：

| 信号 | 怎么算（起点时刻或之前10秒） | 类别 |
|---|---|---|
| 最近的塔是敌方的 | 还没倒的塔和遗迹里离他最近的那个属于敌方；塔的倒下时间从战斗日志读 | 敌方控制区 |
| 在敌方野区 | 离最近的野怪营地≤1200，且该营地在敌方一侧 | 敌方控制区 |
| 是他走向敌人 | 之前10秒里，他缩短的距离占双方缩短距离之和的比例>50% | 主动迹象 |
| 他先动手 | 被打之前10秒内，他普攻或对敌方英雄施放了技能、物品（带技能名的伤害可能是被动反弹，不算） | 主动迹象 |
| 越过己方兵线 | 比己方最近一路兵线的最前沿更靠敌方基地300以上 | 主动迹象 |
| 独自在队友前面 | 比最靠前的存活队友更靠敌方基地1500以上 | 主动迹象 |

“更靠敌方基地”按两泉水连线方向量，这个方向沿三条路都是单调的。塔和营地坐标在`knowledge/awareness/map-zones-v1.json`（塔和遗迹来自本地三场录像的地标采集，营地来自gem-dota的`camp_zones.json`，未用本地录像认证）。组合方式和阈值是助手的初值。

**结果（留出集以外314场，比第二轮多76场是因为解析器v3之后又抽完了一批）**：四个条件都满足的1381段里——被抓死582、交出保命逃掉297、自己深入433（原判被抓死246、原判逃掉187）、高地上69。也就是原来算被抓的里约31%是自己深入。

**开雾**：诡计之雾已从保命手段去掉（`save-means-v2.json`，165项）。有开雾而来的敌人的：被抓死112/582（19%）、交出保命逃掉17/297（6%）。只是记录，不是条件。

**和用户判断的对照**：已判的10个全部一致（5个判对的仍是被抓死；D2、D4、D6归自己深入；D7、D8归高地）。规则是照这10个定的，不能当准确率。同一批60个实例按新规则重新生成了回放（`--sample-from`保持实例不变，判断保留），页面右侧显示六个信号和新归类，地图上画出起点时还在的塔。60个里：被抓死20个中11个仍是被抓死、6个自己深入、3个高地；逃掉20个中13个仍是、5个自己深入、2个高地。

## 11. 第四轮：按23个判断再调（U140，2026-11-11，`reports/gank-episodes-2026-11-11-r4/`）

路线B最后要回答的是“只用当时看得到的信息，能不能提前判断危险”。在动手建模之前先看一眼有没有信号（`scripts/gank_foresight.py`，结果`reports/gank-foresight-2026-11-12/foresight.json`）。

**做法**：第六轮的312场（留出集以外）。正例＝10分钟以后的被抓（死或交保命逃掉），在起点前5、10、20秒各取一个快照；对照＝同一批1号位在10分钟以后每30秒取一个快照，要求活着且前后30秒内没有任何交战段。快照只含己方当时可知的东西：活着的敌人里有几个不在己方视野、有几个已经10秒没见到、最近的活着的队友多远、站位越过中线多少、最近的可见敌人多远。

**结果**（AUC＝随机取一个正例和一个对照，正例这个数更大的概率；0.5是完全没信号，1是完全分开）：

| 特征 | 被抓前5秒的中位数 | 平时的中位数 | AUC 提前5秒 | 提前10秒 | 提前20秒 |
|---|---|---|---|---|---|
| 最近队友的距离 | 5743 | 3161 | 0.69 | 0.68 | 0.65 |
| 看不见的敌人数 | 4 | 3 | 0.64 | 0.64 | 0.57 |
| 已10秒没见到的敌人数 | 3 | 2 | 0.62 | 0.60 | 0.55 |
| 越过中线的深度 | −803 | −2212 | 0.58 | 0.57 | 0.54 |
| 最近可见敌人的距离 | 6047 | 5977 | 0.50 | 0.52 | 0.49 |

被抓前5秒，有4个或5个敌人看不见的占63%；平时是43%。正例约500个，对照16377个。

**怎么读**：

- 有信号，但单个特征都弱，而且越提前越弱（提前20秒时基本只剩队友距离）。
- **其中一部分是定义带来的**：被抓的定义本身要求“最近队友≥1500”和“至少一个敌人从视野外来”，所以正例在这两个特征上天然偏高。真实的可预测性比表里的数低。
- 这些都是单个特征、没有组合，也没有用兵线、塔、敌人最后出现的位置、技能冷却等信息；组合起来会高一些，但这张表不支持“风险分数能做得很准”的预期。
- 对照的取法（每30秒、避开交战）是助手定的；被抓只占时间的很小一部分，实际使用时误报会比AUC看起来多得多。
- 没有做显著性检验，没有按英雄、段位、比赛时间分开看。
