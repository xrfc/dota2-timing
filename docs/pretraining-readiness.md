## 可运行预检

```bash
python3 audit_data.py --preflight --plan knowledge/evidence/feasibility-2026-10-13/expansion-plan.json --discovery data/feasibility-2026-10-13/discovery-response.json --offline --cache data/feasibility-2026-10-13/matches --patch-receipt knowledge/evidence/feasibility-2026-10-13/receipt.json --output reports/preflight-new.json
```

必须使用原发现快照和缓存（本地忽略目录），输出拒绝覆盖。此模式不联网。
**退出码4表示预检已完成但训练held**；2表示输入/输出或证据错误。检查结果不能作为训练授权。
`lineup-preflight/2` 是诊断样本预演，不是 `coach-samples/1`；旧训练入口在启动适配器前拒绝它。
配置 `lineup-preflight-config/1` 默认seed=20261014，验证/测试比例各0.2；少于3场时不生成划分或编码。

输出分开保存：

- `features` / `encoded_features`：只包含英雄身份；`sample_id`、slot、split与来源哈希是元数据。
- `observations`：窗口内源购买键与引用；不是完成标签，不把它当作输入特征。
- `labels` / `label_mask`：目前全部null/false，包括观察到购买的候选。
- `splits` / `preprocessing`：精确比赛列表、仅train词表及编码列序。未知英雄用独立计数，不能在holdout重新拟合。
- `audit` / `exclusions` / `blockers`：完整分母、筛选理由、字段证据和剩余阻塞。

真实固定10场重跑：7场进入预演、2场短局和1场区间外保留排除记录；划分5/1/1，
