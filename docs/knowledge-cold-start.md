# 英雄知识能否作为训练冷启动？

## 2026-10-13 进度同步

公开JSON审计v3与知识冷启动候选是独立证据链；[7场语义核验](data-semantics.md)没有将官方知识、购买行为或规则建议提升为最佳装备监督。

**可以作为冷启动知识和候选监督的基础，但不能直接当作最佳决策训练答案。** 资料入库、来源可靠、机制正确、适合某个训练任务、模型有效是不同层次。

## 已共同确定的目标

回答：某个英雄在当前局势下，下一件值得完成的重要装备是什么？它解决什么需求，是常规思路、反制需求或两者兼有？为什么现在需要？

- 小件有研究价值，魔瓶等早期里程碑保留；树枝、卷轴、消耗品不作为预测目标。
- 主要参考双方英雄、技能与装备；自己的经济和已有零件直接影响完成可行性；双方经济、防御塔、地图、队伍分工等提供背景与紧迫性。
- 选人阶段先理解条件性的能力潜力，不假定技能已学、升级已有或命中成功。
- 先学习当前官网快照，再补历史版本。当前知识不能无条件解释 7.41f 回放。

## 分层用途

| 层 | 目前有什么 | 可以怎样使用 | 不可以怎样使用 |
|---|---|---|---|
| 官方技能事实 | 127 英雄／734 技能，说明与来源哈希 | 查询、检索、带引用问答；形成事实提取候选 | 自动推导克制、出装、最佳操作 |
| 机制理解 | 15 项逐条对照来源的条件说明，其余待核验 | 人工讨论作用对象、限制、代价；设计后续机制题 | 用关键词命中充当正确能力标签 |
| 阵容能力判断 | 能读取双方英雄档案、列出机制证据与未知项 | 分析潜力与需要观察的条件 | 编造强度评分、胜率或组合必胜关系 |
| 装备决策与解释 | 已定义任务，尚缺完整可信监督 | 设计局势—候选—理由—代价的记录方式 | 把实际购买自动标成最佳决策 |

## 本次实际导出

[导出脚本](../knowledge/hero-capabilities/export_cold_start.py)直接读取哈希校验通过的官方中文快照，不从自动关键词标签或模型生成文字构造答案。

```bash
python knowledge/hero-capabilities/export_cold_start.py
```

产物：[734 条候选 JSONL](../knowledge/hero-capabilities/cold-start/candidates.jsonl)及[清单](../knowledge/hero-capabilities/cold-start/manifest.json)，分为 127 个英雄组。每条含：

- 英雄／技能身份、任务类型和唯一样本 ID。
- 原始来源文件、网址、JSON 指针、SHA-256 与快照 ID。
- 官网说明、注意事项及神杖／魔晶条件；不推算占位参数。
- `status=candidate_not_training_admitted`、`training_allowed=false`。

它是**来源提取候选**：输入与输出保留同一组事实，适合将来验证摘录／结构化输出协议，不能当作独立推理监督，也不是已可直接上传给某个训练服务的完整格式。导出没有执行训练、划分训练集或修改回放准入。

## 建议的冷启动顺序

1. **先检索后解释**：以冻结知识库支撑回答，核验是否忠于来源；更新知识无需重训权重。
2. **机制理解样本**：逐条核对后再构造题目，解释控制区别、作用方向、限制和升级条件；覆盖不知道／条件不足的回答。
3. **阵容功能样本**：由相关技能证据支持功能与缺口判断，不把英雄标签直接相加。
4. **装备决策样本**：加入可信局势、候选装备、机制关系、可行性、备选与代价，才可能训练我们的目标任务。

仅把文本转成向量或放进提示词不是训练模型；SFT 是学习输出行为；决策网络还需要定义特征、目标及损失。这三种用途不混称为同一个冷启动训练。

## 训练前与评估时需要完成什么

- 明确任务、模型类型、版本、内容使用条件和核验范围；不把当前官网快照当成所有历史版本的真值。
- 检查技能解释、否定句、目标方向、升级与环境条件，不依据“字段非空”准入。
- 同一英雄的语言版本、技能、升级和改写样本按组处理；训练／评估分组必须服务具体泛化目标。未见英雄评估与已知英雄新局势评估需要分别报告。
- 防止改写泄漏：从一条来源改写多道题，不等于得到多条独立知识。知识文本开放检索的评估必须标为检索评估。
- 回放样本仍按独立比赛及必要的时间／版本范围隔离，不能随机拆同局时间片；不能加入未来或玩家不可知信息。
- 除提取准确率外，检查机制区别、条件保留、引用支撑、未知处理、升级误用和事实错误；出装质量需要另外的可信评估。

当前没有新模型权重、训练执行或决策效果结果。真实回放训练准入仍为 held；这些候选也尚未准入，不因发布到 GitHub 自动改变。
