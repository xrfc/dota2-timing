## M2 出装时间预测：第一次真实训练

**任务形式**：把“几分钟做出狂战斧”转成5个二分类问题（10/15/20/25/30分钟前是否做出）。这是处理“时间到事件”问题的最简单做法；更正规的方法叫**生存分析**（survival analysis），以后可以学。

**基线（baseline）**：不看阵容，直接用训练集的平均概率。任何模型都要先打败它才有意义。

**逻辑回归**：`p = 1 / (1 + e^-(w·x + b))`。x是阵容的one-hot向量（某英雄在敌方→对应位置为1），w是每个英雄的权重，b是截距。训练就是找让训练数据“最不意外”的w、b（最大似然）。

**正则化（L2，参数C）**：在目标里加`‖w‖²`惩罚，防止权重过大。C越小惩罚越强。

**评估指标**：
- Brier分数 = 预测概率与0/1结果之差的平方平均，越低越好；
- 对数损失（log loss）对“很自信却错了”惩罚更重；
- **bootstrap置信区间**：把验证集按比赛重复有放回抽样1000次，看“模型比基线好多少”的波动范围。区间含0就不能说模型更好。

**冻结协议**：指标、基线、展示规则在训练前写死。否则人会不自觉地“调到验证集看起来好”，这叫**对验证集过拟合**，也是论文结果复现不了的常见原因。

**这次的结果——过拟合的典型样子**：
- 约250个特征、巫医只有约160个样本：每个英雄只出现几次，模型把巧合当规律，在没见过的验证集上反而更差。
- 神谕者35项里有3项“显著更好”，但验证只有15人：做很多次检验，总会有几次靠运气通过，这叫**多重比较问题**。

**可能的改进（下一步要学的概念）**：
1. **交叉验证选超参数**：在训练集内部轮流留一部分做验证，选出合适的C，全程不碰正式验证集。
2. **特征工程/降维**：把127个英雄压成几类属性（控制多、物理爆发、魔法爆发…），参数少了，样本才够用。
3. **共享参数/层级模型**：让四个英雄共享“敌方有控制→出BKB”这类规律，而不是各学各的。这正是以后学深度学习时“嵌入（embedding）”要解决的问题。
