# 边做边学：项目里的机器学习（2026-10-30起）

看见某次收线后英雄存活，只能核实这次收线的结果。若模型估计其中一种动作在该局面的选择概率低于 5%，两种选择缺少共同的参照。即使两种动作都有样本，也要检查加权后两组的局势是否相近。[B5 试用中的两种比较限制](../../docs/outcome-autotrain.md#三场玩家试用)

复盘决策要重建玩家当时能看到的地图。敌人离开视野后，仍可沿用最后一次可见的坐标和时间；再用该敌人此刻的真实位置，就把对局面判断最重要的不确定性抹掉了。[一方视角实例](../../docs/outcome-autotrain.md#片段地图)

同一片段里，录像行只记录该玩家实际采取动作后发生的事；两个估计行来自相似历史局面。并排读支援到场率与自身死亡风险时，要同时保留两项概率和各自的观察窗口。[B5 页面](../../docs/outcome-autotrain.md#本机复盘页面)

同一份报告有三个不同的分母。三场录像触发 109 个机会，能识别动作并核对后果的有 65 段，其中只有 29 段的历史数据足以比较两个动作。逐段核对录像能发现标签或时间窗错误；玩家从未选择的动作仍需要用相似局面估计。[三场实例](../../docs/outcome-autotrain.md#三场本机结果)

开发集中一场比赛即使没有生成可评片段，也已进入研究样本选择流程。核对新录像独立性时，要用建表前确定的比赛底册，再用冻结数据指纹核对各场景的片段。报告中把触发机会、可评后果、有双动作支持及达到平衡门槛的片段分别计数，才能看清覆盖在哪一步收缩。

整场留出可以检验模型能否预测其他比赛里实际发生的后果。即使留出误差和开发折外误差接近，落选动作仍然只能靠相似局面估计。[单次评估](../../docs/outcome-autotrain.md)

支援标签可以要求自己与受击队友同秒接近。它容易复算，但若支援本身使对方停止追打，这个标签反而可能为零。 [研究实例](../../docs/outcome-autotrain.md)

倾向得分接近 0 或 1 时，少数样本可能支配加权均值。把未覆盖片段和有效样本量报出来，才能判断模型的行动比较适用于哪些局面。 [研究实例](../../docs/outcome-autotrain.md)

金钱余额的下降可能来自消费。经验读数跨升级时语义存疑，按标签屏蔽这些窗口可避免把升级误报成经验损失，也会低估高收益片段的覆盖。 [研究实例](../../docs/outcome-autotrain.md)

试点在每个验证折都有两种动作且有正负死亡标签时停止。这个条件让小样本实验能计算指标，却无法说明指标对更多比赛是否稳定。扩大样本后沿用同一筛选条件、按场划分和模型，才能比较试点与全量的结论。[全量研究](../../docs/outcome-autotrain.md)
