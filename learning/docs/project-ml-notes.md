# 边做边学：项目里的机器学习（2026-10-30起）

## 2026-11-26：营地证据与信息边界

- 录像解析器能知道整张地图，不代表玩家当时知道。先保存可审计的原始状态，再只投影己方实际可见单位；测试应证明改动隐藏单位或未来事件不会改变当前公开事实。
- 没有可见单位、缺少视野字段、确认空营是三种不同情况。前两者都不能直接编码成“营地库存为零”；否则模型会把不可观测当成游戏事实。
- 同一 tick 可能有多个回调；事前状态必须固定首个回调。后续补齐字段虽能减少空值，却可能把结果之后的信息倒灌到决策时。
- 实体 index 会重用，需配 serial。具体单位名和通用实体名分别查 UnitNames 与 EntityNames，不能只凭名字前缀推断野怪归属或收益分类。
- 金额核验和机制解释也分层：原始计数与钱包能证明非击杀者确有收入，却未必能证明奖励原因。保留未知，比用一个相似比例补出故事更可靠。
- 真实回归里，可见单位中既有受控野怪，也有尸体。active 只指实体仍在当前活动表中，不等于存活或可刷；保留生命状态，才能在后续研究中明确怎样定义可清营条件。
- 后续记录中的四个单位身份，事前帧可能只出现一个。其余不能倒填，也不能从“当时没读到”推断“尚未出生”；原始缺失和机制解释须分开。
- `observed` 是解析状态，不是知识完备性。即使所有请求帧都取得观察者身份、公开字段也没有空值，仍不能推出完整地图视野或营地存量；字段覆盖率必须说明分母只包含实际公开的单位。
- 全集 15,005 帧中 2,439 帧没有可见中立类单位，7,594 个动作仍未知。提取完整只证明每个固定机会都有结果；它既不会把未知动作变成训练标签，也不会把反复看到的 179,149 条单位记录变成同样数量的独立野怪。按动作、比赛 fold 和阵营核对覆盖，是为了发现漏数，不是在比较行动效果。
