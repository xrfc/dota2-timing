# 边做边学：项目里的机器学习（2026-10-30起）

## 2026-11-26：多版本有三道不同的验证

格式可读、迁移预测等价、在另一个游戏补丁上仍然有效，是不同结论。来源SHA保留历史身份，消费者SHA和验证证据说明新代码能否读取它；不能用同一个schema号代替两者。旧模型可以覆盖多个补丁，但每个目标上下文必须有独立证据，不能把合成测试通过当作跨补丁效果已验证。

支持周期区分正常支持、仅历史复现、停止运行，并在到期/撤销时拒绝使用。此次M1先实现纯内存契约，不填写真实兼容批准项。

## 2026-11-26：兼容不只是“原来的import还能用”

旧joblib会依赖对象的类路径，旧流程还校验整份源码指纹。因此把脚本改成同名转发门面，可能能加载类，却不能通过原来的来源校验。D5选择先保留旧代，新增分层实现，再用精确登记的转换桥复制已拟合状态；“转换”不等于重新训练，也不等于重新独立验收。

新格式用数据字段表示项目自定义状态，避免继续把自己的类路径写入pickle；sklearn树/Pipeline仍有版本依赖，不能声称完全脱离训练库生态。manifest绑定载荷，转换收据再绑定manifest，避免两个文件互相嵌入哈希而无法生成。

模块迁移也不能改研究问题：U191现金差和farm/retreat不能直接替换为新B5分类实收和收线/转野。设计中的合成parity用于检查等价，不读取已评分的337场。详见[迁移设计](../../docs/action-model-migration-design.md)。


若录像提前结束，已经记录的后续受击能支持“估计到场时仍有受击”，但无法证明较晚的路线必然错过后续事件。
