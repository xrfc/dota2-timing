# 边做边学：项目里的机器学习（2026-10-30起）

## 2026-11-26：低耦合也需要可检验的保证范围

本轮发现原架构检查能限制包之间的导入，却漏了脚本裸导入；专项测试登记齐全也不代表覆盖了模型实际调用方。已增加脚本边界、静态无环和测试导入检查，并保留跨层测试的双归属。

低耦合可以从四处判断：代码依赖方向、运行时加载、文件契约、职责分工。静态无环不证明动态装载无环；预测函数存在不证明导入它不加载训练库；两个工具用同一核算函数复算不等于独立算法。相反，消费者精确绑定公开交接 SHA 是有意约束版本，不应为“灵活”取消校验。

PR #34 的模型类仍在 scripts 中，且旧 joblib 记录了类的模块路径；它虽没有跨线导入，仍存在职责和持久化耦合。后续应先设计兼容迁移，再让新实现归 modeling、运行编排归 experiments。测试只导入脚本也可能避开自动的 modeling scope 检查，因此结构检查不能替代接口评审。

科研进度也要分开：完整提取和独立金额核验提高了输入可信度，不证明推荐有效。可见活单位不等于可刷营地；未知保留并允许弃权，比补成零更能避免自欺。原337场已经评分，未来模型需要新独立证据。当前实验仍应先定受限任务、同目标简单基线和整场分组比较。
