## 方法、来源与局限

逐组查看全部候选fact的完整指针值，并回读对应完整基础说明（英文及候选引用的中文），不是截断quote。装备附注组同时回读装备技能完整说明。中英文同义片段不作为两份独立证据；指针读取、基础说明、附注等完整原值留在`source-reads.jsonl`供追溯，其中还保存可供后续检查的附注，不把机器保存等同于逐句人工认证。

这是知道Claude判断及用户结论后的复核，不是盲审；逐项判断写在`codex-review.jsonl`。97组先天接受按U33统一规则处理，字段只证明被动分类，**不证明游戏引擎受破坏行为，也不证明英雄怕破坏**。每组保留原文触发条件及单独理由；未运行游戏。

U36已确认英文技能与11-01官网快照一致（中文有翻译修订），很可能7.41f，但仍保持`patch_verified=false`。以仓库快照为准，不按游戏记忆覆盖文字；本轮没有以记忆提出机制事实反判。官网说明可能与游戏实现不符的情形应由用户实测，不把文本复核视为实测。装备仍是OpenDota社区快照，未因此获得官网当前版本认证。本次没有联网采集或训练。

## 过时升级文字：仅核对19组的移除依据

`stale-upgrade-review.jsonl`中accept表示“支持从当前升级证据中隔离”，**不是对机制语义的accept**，`semantic_decision=null`。单独存储、单独计数，不与Claude第1轮语义标签比较。

逐项核对10-09与11-01英文原始响应：19组对应的`ability_has_scepter/shard`均为**显式false**，同升级的`ability_is_granted_by_scepter/shard`也均为false；未发现由该升级授予的技能被误排。这仅支持这19组，不授权将缺失字段当false。v3仅隔离对应升级文字的facts，不否定基础技能机制，更不否定升级文字本身的历史语义。

反例控制：狙击手·震荡手雷has_shard=false但granted_by_shard=true，应保留；`granted-ability-controls.json`与源码检查确认v3跳过此类授予技能。v3函数目前用`not get(...)`判断，未来数据若缺字段应另行检查，不把这19项明确false核验推广成所有输入健壮性结论。
