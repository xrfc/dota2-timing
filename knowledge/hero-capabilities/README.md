# Dota 2 选人阶段能力理解：第一版

## 当前交付

2026-10-10：官方当前英雄列表中的 **127 位英雄**均建立了能力档案，共 **734 个技能条目**；中英文原始详情共 **254 份**。全部英雄身份与固定提交的 OpenDota 目录一致，技能没有缺失英文说明或中文关联。

- [全英雄索引](HEROES.md)：逐英雄阅读官方技能说明、注意事项、升级条件和源数值。
- [能力评估定义](ASSESSMENT.md)：哪些问题需要判断，哪些结论不能凭选人直接得到。
- [覆盖检查](coverage.json)：档案覆盖不等于机制解释已全部核验。
- [来源清单与哈希](source-manifest.json)：记录原始来源、读取时间和内容指纹。
- [结构化全英雄档案](hero-registry.json)：供评估读取，不是已经准入的训练特征。
- [双阵容示例](draft-example.json)：读取全部十名英雄档案，列出潜在机制和未知项。

**完成的是全英雄官方能力资料解构和评估输入范围，不是全英雄战术评分。** 自动文本检索只产生待核验线索；本地逐条核对的 15 项说明也仍是当前快照的条件性陈述，不是历史版本认证或用户的战术认可。

## 与我们共同定义的任务对齐

目标：某个英雄在当前局势下，下一件值得完成的重要装备是什么？常规思路、反制需求可以同时存在，必须说明需要它的具体原因。

- 研究小件与早期里程碑，不只研究昂贵大件；魔瓶等保留。
- 树枝、卷轴、消耗品不作为出装预测目标；本模块不统计购买频次。
- 优先分析双方英雄技能和装备；自身经济、已有零件决定可行性；双方经济、防御塔、地图及队伍分工等提供局势条件。
- 首先建立选人阶段的能力潜力判断，再用比赛中可见信息更新；不把实际购买自动视为最佳决策。

## 来源选择与版本边界

采用现成公开数据而非手写英雄数据库：

1. Valve 官方 [英雄列表](https://www.dota2.com/datafeed/herolist?language=english)，逐英雄 `herodata` 中英文说明和数值。
2. OpenDota [dotaconstants](https://github.com/odota/dotaconstants)，固定提交 `bf193a550f778dec35debf4d71d05a86bebcc418` 的英雄身份和已发布角色标签。角色标签是宽泛定位，不是实际分路、战术评分或当局强度。

用户已于 2026-10-10 确定顺序：**先学习当前官网版本，再补历史版本**。当前学习范围为 `current_official_snapshot`，不再默认以 `7.41f` 为目标。来源详情接口没有返回明确 patch 字段，因此 **source_patch=null、target_patch=null、patch_verified=false**；这不妨碍学习该官网快照，但当前资料不能直接用于历史回放的反制或出装结论。

有些技能说明含未替换参数占位符，有些升级／命石文字可能残留；不猜数值，不假定现行，也不把原始枚举值自行翻译成减益免疫穿透、驱散等级等结论。中英文描述可能不完全一致，冲突需要另行核对，不能用一个语言自动覆盖另一个。

## 本次选人示例

仅沿用比赛 `9031371970` 的英雄组合，演示当前快照的检索与条件陈述。**不是对该历史比赛的正式分析**，也没有使用其未来战斗、经济或装备。

| 阵营 | 英雄 |
|---|---|
| 天辉 | 灰烬之灵、斯温、干扰者、末日使者、祈求者 |
| 夜魇 | 米拉娜、瘟疫法师、凯、森海飞霞、大地之灵 |

我们能建立的基本机制判断：

- 灰烬之灵炎阳索提供缠绕，不能计作眩晕；附近目标选择与目标状态有限制。
- 斯温风暴之拳说明包含范围眩晕，分裂攻击说明包含攻击分裂；不能直接换算为先手成功率或清线速度。
- 干扰者静态风暴有区域沉默；禁用物品属于神杖升级，不是基础选人能力。
- 米拉娜箭矢的控制需要命中，时长与飞行距离有关；不能与无条件稳定控制等同。
- 森海飞霞野地奇袭依赖树木，树被摧毁会解除眩晕。
- 瘟疫法师幽魂护罩说明有无法攻击／被攻击的防护，也有受到魔法伤害增加的代价；不能贴“全面更耐打”的标签。
- 凯的武器切换影响技能组合和冷却关系；不能把所有技能默认同时可用。

上述说法的原始中英文、注意事项和路径均保存在示例 JSON。其余维度可以检索技能资料，但没有已核对条目时标为未知或待核验，不能填成“没有”。没有输出哪方更强、胜率或装备推荐。

## 如何运行

在 workspace 根目录：

```bash
# 重建档案：先核对原始快照哈希，不需联网。
python3 knowledge/hero-capabilities/build_profiles.py

# 更换双方英雄 ID，生成选人能力证据清单。
python3 knowledge/hero-capabilities/draft_assessment.py \
  --radiant 106,18,87,69,74 \
  --dire 9,36,145,123,107

# 检查不把升级当基础、不把未知当缺失、拒绝无效阵容等边界。
python3 -m unittest discover -s knowledge/hero-capabilities -p 'test_*.py' -v
```

初版 9 项边界测试通过。当前目录已迁入仓库，作为独立能力理解与知识候选模块；不属于正式工程包，也未接入真实训练入口。迁移及路径映射见[知识维护与路径清单](../../docs/knowledge-maintenance.md)，冷启动用途见[训练用途说明](../../docs/knowledge-cold-start.md)。回放证据和真实训练准入状态未改变。
